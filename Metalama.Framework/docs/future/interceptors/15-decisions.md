| Call-site forwarders (2026-10-04, review of #2107 and metalama/Metalama.Premium#111) | No `using` directive is ever added, and the extension form is never used against a method written by the user. An ordinary call site keeps the fully qualified static form, `global::Shop.Hooks.Validate( order, 3 )`. A call site in a conditional access, `order?.Validate( 3 )`, is rewritten as a call of a forwarder, `order?.__Shop_Hooks_Validate( 3 )`. The forwarder is a public static extension method with the parameters and the type parameters of the target, whose body calls the target with its fully qualified name and which has `[MethodImpl( MethodImplOptions.AggressiveInlining )]`. The receiver stays in the conditional access, so the compiler evaluates it once, does not evaluate the arguments when it is null, and lifts the result; `a?.B.M()` and `a?.B?.M()` work unchanged. The linker generates one forwarder per target method, shared by all the call sites of the project, in one internal static class of the global namespace named `__MetalamaCallSites_<assembly name>`, in one syntax tree per project. The name of a forwarder is the namespace, the declaring types and the method name, separated by underscores, after two underscores; an underscore of a source name is doubled, and a generic type is written with its arity (`Hooks_1`). The public receiver mode `ExtensionReceiver` is removed: the factory uses a forwarder for a request with `FirstArgument` in a conditional access, and refuses the other modes there. The factory verifies the binding on the static form of the call, because the forwarders of the overloads of a method mirror them; it also refuses a receiver that converts to the first parameter by another conversion than an identity, reference or boxing conversion, a target that a top-level class cannot access or that an aspect introduces, a signature that cannot be copied, and a name that already designates a member on the receiver at the call site, which covers the forwarders of a friend assembly visible through `InternalsVisibleTo`. A generic forwarder is called with explicit type arguments, those of the static form. No design-time counterpart is needed, because the design-time pipeline does not rewrite call sites. The premium engine no longer requires an extension interceptor in scope for a conditional access, and `IsExtensionMethodInScope` is removed. Rejected alternatives: `using` or `using static` directives, which change the lookup of names and extension methods in the whole file of user code; a delegate helper `IfNotNull( x, () => ... )`, which allocates a closure, while a static lambda evaluates the arguments eagerly and breaks the semantics of `?.`; the pattern form `a is { } t ? Hooks.Validate( t, 3 ) : null`, which is correct but leaks a pattern variable into the enclosing block and reads worse; a second evaluation of the receiver, which is safe only for locals and parameters and races on a field. |

The implementation of the transformation factory in M0 differs from sections [10.4](10a-oss-bridge-hook-factory.md#104-extension-transformation-factory-b2c) and [10.5](10b-oss-linker-and-templates.md#105-linker-changes) on the following points. These are engineering choices, not decisions of the product owner.

- The linker writes every argument of a redirected call with its parameter name and in the order of the source call. C# evaluates named arguments in the order in which they are written, so a reordered argument list keeps the original order of evaluation without temporary variables, without a block in a statement context and without pattern variables in an expression context.
- A source argument that the new argument list omits, and that can have a side effect, is evaluated in its source order (PO72) by a call of `Metalama.Framework.RunTime.CallSiteHelper`, a public run-time helper of `Metalama.Framework` that is hidden from IntelliSense: `DropBefore( D, next )` before the next argument passed by value, or `DropAfter( previous, D )` after the previous one when the next one cannot hold it. C# evaluates the arguments of a call in the order in which they are written, so the order of the parameters of each method is the order of evaluation, and each method returns the kept value. A single dropped value is passed as it is. Several consecutive dropped values are packed into one tuple literal, in the source order. Dropped values on both sides of one kept argument nest: `DropBefore( D1, DropAfter( keep, D2 ) )`. The type arguments are inferred when the kept value has a natural type that converts implicitly to the type of the parameter. Otherwise, for instance for `default`, `new()`, `null` or a collection expression, both type arguments are written: the type of the parameter of the target for the kept value, so that it is converted as in the original call, and the natural types of the dropped values. A dropped value without natural type is written with the type of its parameter. The factory refuses an omitted argument that is passed by reference, an omitted argument that no adjacent argument passed by value can hold, a dropped or kept value of a ref struct or pointer type, which cannot be a type argument, a type that cannot be written when the type arguments must be written, an interpolated string handler, and a dropped argument whose conversion to the parameter calls a user-defined operator. An argument in parentheses or with a suppressed nullable warning is treated like the same argument without them. An omitted argument without side effect, such as a constant, a local, a lambda or a field of `this`, is not evaluated. The helper replaced the switch-expression forms `D switch { _ => next }` and `previous switch { var t => D switch { _ => t } }` (decision of 2026-10-03 on #2107), which were rejected as unreadable. A call whose arguments are all dropped is refused until the temporaries of M3.
- The target of a redirection must be a static method. Instance targets and the call-site mode `MemberOfReceiver` are added with the receiver rule R2 in M3.
- `RedirectedArgument.Value` takes an `ExpressionSyntax` instead of an `IExpression`, and `CallSiteExtraArgument.FromConstant` is not provided. The caller creates the syntax.
- `RedirectedArgument.WithCast( type )`, which section 10.4 does not have, casts a source argument passed by value, `(T)(argument)`. It writes the cast of rule E10 (section [6.6](06b-signatures-and-validation.md#66-signature-validation-existing-methods-and-adjusted-signatures-r9)) without replacing the source argument by an expression, so the redirections nested in the argument are kept.
- `RedirectedArgument.PackedSourceArgument` is not provided. `RedirectedArgument.SourceArgument( i )` packs the elements of an expanded `params` argument into one collection when the argument list is planned: a collection expression from C# 12, which creates the same collection as the compiler, also for a `params` collection, and an array creation before C# 12, with `Array.Empty<T>()` for no element. The elements are evaluated in their source order.
- The factory, and not the premium engine, makes the speculative binding of rule E16. It binds the rewritten call exactly as the linker writes it, at the position of the call site, and refuses the request when the call does not bind to the target, for instance because an overload of the target without its optional parameters is preferred, or because an instance method of the receiver hides the extension method of the target. A call in a conditional access is bound with the receiver `default(T)`, where `T` is the type of the receiver in the conditional access. The factory also binds a redirected method group in its statement, initializer or expression body (rule E18), so that a method group that selects another overload of the target, or that has no natural type because the target is overloaded, is refused. Every client of the factory therefore gets both checks, and the premium engine reports a refusal with LAMA1013. Both checks are skipped when the target has no symbol in the compilation of the call site, which is the case of a method introduced by an aspect, and the check of a method group is skipped in a context without a speculative semantic model, for instance an attribute argument.
- `LinkerNamingServices` and `ExtensionTransformationFactoryContext` are not created in M0, because no M0 request introduces a member.
- The redirections are tested by the aspect tests of the proof of concept (`Metalama.Framework.Tests.AspectTests.ExtensionPoints`, folders `Redirection` and `MethodReferences`) instead of linker tests with pseudo-attributes. The proof of concept exercises the public API end to end, from an aspect and from a fabric.

The implementation of change S1 (metalama/Metalama#2098) makes the following choices.

- Superseded by the decision "Design-time source stage only" (2026-10-04): `DesignTimeContributorsContext` passed all the contributors of the stage together with `ContributorsAddedInStage`, `HighLevelStageIndex` and `NewContributors`, and the extensions that return transitive contributors built them from `NewContributors`. The hook now runs only in the source stage, and the context passes only the contributors and the compilations of that stage.
- The design-time result keeps the transitive contributors of the source stage, which the pipeline carries to the result of the last stage.
- The design-time stage also accumulates the inheritable aspects and the transformations, which it lost in the same way. The transformations feed the code lens and the aspect database.
- The compile-time linker stage still publishes only the transitive contributors of its own stage, so the compile-time transitive manifest loses those of the earlier stages in the same way. The fix needs a context object for `ExecutePipelineContributorsAsync` first, because that hook also receives the replayed contributors in every stage. It is tracked by metalama/Metalama#2108.

The review of the M0 stack on 2026-10-03 led to the following corrections and records.

- A call in a chain that starts with a conditional access, such as `a?.B.M()` or `a?[0].M()`, is a conditional access: its receiver exists only in the conditional access. The receiver-passing modes are refused for it, and `ExtensionReceiver` is accepted, as for `a?.M()`.
- The receiver of a base call to a virtual method cannot be passed, with any receiver mode, because the target would call the method with a virtual dispatch. `Drop` with `RedirectedArgument.SourceReceiver` is otherwise the way to pass the receiver of an instance call to a static target at any position of its parameter list, although `CallSiteReceiverMode.Drop` is described for static calls.
- `ExtensionReceiver` on `p->M()` writes `(*(p)).I()`.
- A result cast is refused when the target returns `void`, and when the call is a statement, including the body of an expression-bodied member or lambda that returns `void`, because a cast expression is not a statement.
- A source argument is passed to a parameter of the same reference kind, with three exceptions: a value to an `in` parameter, and an `in` or `ref` argument to a `ref readonly` parameter. The other combinations produce the warnings CS9191 to CS9193 in the rewritten call.
- The factory is synchronized with a lock, while section 10.4.1 describes it as not thread-safe. The identifiers of the redirections, which order the LAMA0660 warnings of a syntax tree, follow the order of the requests, so they depend on the order in which concurrent extensions make them.
- The factory does not know expression trees. It rewrites a call in an expression tree like any other call, and its clients decide (PO11).
- `MethodReferenceRedirectionRequest` has no `WrapperDelegateType`, `WrapperArguments` or `DelegateParameter`. The wrapper of a method group comes with the bindings of M2.
- The origin captured from a project fabric resolves its aspect layer through the full name of the fabric type.
- `ExtensionContributionOrigin` has no `PipelineStepIndex`. `IAdviceFactoryImpl.CreateExtensionContext` takes no target, because the target is the target of the adviser. `ExtensionContributionOrigin.DefaultTemplateProvider` falls back to the aspect or to the fabric, so it is not nullable. `AdviserExtensionContext.CaptureOrigin` and `ExtensionContributionOrigin.Capture` throw an `ObjectDisposedException` when the aspect has finished executing (section 10.2.3).
- `ExtensionTransformationContext.SourceCompilationWithFinalAspects` was available only when `IsSourceStage` was true. Superseded by the row "Source stage only": the hook runs only in the source stage, and the property no longer throws.
- The index covers the source compilation of the pipeline, so the declaration roots must be nodes of the source compilation. Since the row "Source stage only", the index is built only in the source stage. `SourceReferenceIndexService.BeginStage` refuses another root with an `ArgumentException`. The index is built outside of the lock of the stage. `BeginStage` takes the requirements without the consumers. `DesignTimeAspectPipelineResultExtensionCollection.IndexOptions` adds the requirements of the design-time results of the project to `Options`, which referencing projects merge. `SourceReferenceIndexStage.HasRequirements` and `IsRestrictedToDeclarationRoots` are additions. `GetDesignTimeIndex` has no production caller until Phase B.
- An inspection-only expression cannot be made durable: `ExpressionExtensions.ToDurable` throws an `InvalidOperationException`.
- The reference walker also tests `IsCurrentDeclarationInRunTimeCode()` in `VisitCollectionExpression`. It visits the nested types of classes, structs, records and unions when it does not descend into members, and it processes `Nullable<T>` written as a generic name, in a qualified name or as the element type of an array, as `T?`. These changes are part of the release note of F1.

The implementation of the open-source items of M1 makes the following choices.

- LAMA0295 is no longer free: metalama/Metalama#2052 uses it for `CantResolveDeclarativeAdvice`, after the check of PO41. The inspection-only source expressions use LAMA0297 as planned. `AnyAwaitable` (section [10.6.9](10b-oss-linker-and-templates.md#1069-anyawaitable)) must take another identifier than LAMA0295 for its `ConfigureAwait` diagnostic.
- An inspection-only expression is also refused by the textual conversion of expressions (`IExpressionHelper.ConvertExpressionToText`), which can produce generated code, and not only by the template expansion.
- The emission of an inspection-only expression is tested by the aspect tests of the proof of concept (folder `SourceExpressions`), through a verb that creates the expression, instead of template tests. Template tests have no way to obtain such an expression, because only an extension can create it.

The public API of `Metalama.Extensions.Interceptors` in M1 (metalama/Metalama#2097) is the subset of section 5 that M1 needs. The members of later milestones are added with them.

- Only `InterceptMethods` exists, with the four target selections and the provider, delegate, existing-method, template-shorthand and factory forms, on `IQuery<T>`, `ITaggedQuery<T, TTag>`, `IAdviser<T>` and `ITypeAmender`. `InterceptAccessors`, `InterceptAwaits` and their types come with M2 and M5.
- `InterceptionContext.SupportsPlacement` comes with the placements of M2. The accessor members of `MethodInterceptionContext` (`AssignmentOperator`, `IsPostfix`, `IsChecked`), `InvocationArgumentKind.Computed`, and the accessor and await reasons of `NonInterceptableReason` come with accessors and awaits. The await members of `InterceptorResult` come with M5.
- `IInterceptorMethodBinder` and `IInterceptorBuilder` exist without members, so that the `bind` and `configure` parameters have their final types. The engine of M1 reports a `bind` or `configure` function, and every template result, as not supported in this version.
- The internal `InterceptionRegistration` describes method registrations only, and `InterceptorDefinition.FromFactory` takes a typed factory of `IMethodInterceptorProvider`.
- The package has no reference to `Metalama.Licensing`, because it is available under the Community license (PO3).

The engine of M1 implements the compile-time run of section 9.5 for existing static methods. It makes the following choices.

- A registration made through an adviser is converted to a query of the adviser target, created by the adviser context. The containment check of section 9.4.3 is made at registration, and LAMA1000 is reported by `ExecuteContributorsAsync`.
- The engine returns no declaration roots to the shared index. The names of the registrations already restrict the binding to the bodies that contain them.
- The speculative binding of the rewritten call (rule E16) is made by the factory of transformations, as described above for M0. A refusal is reported with LAMA1013.
- A by-value argument whose natural type differs from the type of the parameter of the target, and whose parameter of the interceptor has another type than that parameter, is cast to the type of the parameter of the target (rule E10), with `RedirectedArgument.WithCast`. A target-typed argument is still refused in that case, as E10 requires.
- A dropped argument with side effects (PO72) is evaluated by the factory of transformations with `CallSiteHelper`, as described above for M0. When the factory refuses the request, for instance because the dropped argument is passed by reference, the engine reports the refusal with LAMA1013.
- The arguments are rearranged only when the binding requires it: an argument is dropped, or a positional argument would not bind to the parameter of the same name. When a call that passes the elements of a `params` parameter in expanded form is rearranged, the factory packs the elements into one collection.
- Instance interceptors (rules R2 to R4), placements, templates, accessors and awaits come with the later milestones.

The review of the M1 stack on 2026-10-03 led to the following corrections and records.

- The classification of a struct receiver follows the rules of the C# compiler for the cases that M1 supports: `p->M()` modifies `*p` in place, a readonly field can be modified only through `this` in a constructor, an `init` accessor or a field initializer of its type, and a primary constructor parameter of a struct is read-only in a readonly member or in a readonly struct. Ref fields, implicit indexers, `ref` conditional expressions and `ref` assignments are not classified, so they are treated as values, which is the conservative choice.
- A type argument that cannot be written, such as an anonymous type, is not written in the rewritten call: the compiler infers it again, and the binding check of the factory verifies the call. A method group with such a type argument is refused.
- A receiver whose type is a type parameter is refused with LAMA1013, because an existing method cannot receive it in M1. The members `NonInterceptableReason.CovariantArrayElementReceiver` and `ReceiverReassignedByArguments` are not produced in M1.
- A source argument is passed to a parameter of the same reference kind, with the exceptions described above for M0 (rule E9).
- A call to a C# 14 extension member binds to the member of the extension block, so it never matches a registration on the static class. LAMA1008 reports the name with an explanation. Extension members are not supported in M1.
- The registration diagnostics of a project fabric, of a namespace fabric and of an aspect applied to the compilation are located at the class of the fabric or at the attribute of the aspect, because the compilation has no location.
- An exception of a provider is reported on the declaration that contains the site, and an exception of a type predicate at the location of the user code that threw it.
- The sort key of a registration contains the location of the attribute that created the aspect instance, through the chain of predecessors, and the assembly of a fabric, so that two instances of the same aspect on the same target, and two transitive fabrics with the same name, have distinct keys.
- The method-reference signature mismatch, LAMA1019 in the plan, is reported as a refusal reason of LAMA1013.
- The `generated_code` option of the analyzer configuration is not consulted. A file is generated when its name or its header says so.
- The diagnostics of the run are reported to one sink, not to one sink per syntax tree.
- `InterfaceImplementations` matches the implementations of the interfaces of the containing type of the called method, so an implementation inherited from a base class that does not implement the interface does not match.
- The design-time form of a registration keeps the scope, the registration and the provider of a factory. It has no `IInterceptorRegistrationDescriptor`, `ScopeContainingTypeKey` or `Matching`, and it does not keep the aspect state.
- An existing-method shorthand whose method does not resolve in the compilation of the run is ignored by the collector. No scenario of the tests produces it: a method introduced by an aspect resolves, and the validation of the site refuses it with LAMA1013.

The second round of the review on 2026-10-03, which addressed the minor findings and the gaps of the tests, led to the following corrections and records.

- The factory of transformations refuses a null origin or request with an `ArgumentNullException`. With `FirstArgumentByRef`, it binds the rewritten call in a copy of its syntax tree and refuses a receiver that is not a writable variable, because a speculative semantic model reports no diagnostic. An ordered layer created from the name of an aspect type, which only tests create, is refused with an `ArgumentException` instead of an assertion.
- The refusal of a discard below C# 9 could not be reached, because Metalama requires C# 10 or later (LAMA0052). It was removed with the switch-expression forms, because `CallSiteHelper` needs no recent language version.
- In the `FirstArgument` modes, the receiver is not an item of the argument plan, so it cannot hold a following dropped value. A call `r.M( F() )` redirected to `I( r )` without `F()` is therefore refused, although the receiver could hold it.
- The members of C# 14 extension blocks are accepted as call sites but not tested. As a target, the factory refuses them, because they are neither static methods nor classic extension methods, although section 10.4.8 lists them. They come with a later milestone.
- Section 10.5.10, the removal of the redirections to targets that a preview does not observe, is not implemented. M0 redirects only to existing methods, so no target can be missing from a preview. The removal comes with the synthesized targets of M2.
- F15 cannot be reached in M0 and M1. The linker writes the introduced types in separate syntax trees, and no transformation injects members into a namespace or a compilation unit of a source syntax tree. Its test comes with the synthesized classes of M2.
- LAMA0297 is reported on the target of the aspect, not on the source expression, because `UserCodeInvoker` reports every diagnostic of user code on the target declaration of the aspect.
- At design time, `DiagnosticQueryPipelineExtension` evaluates the queries in the source stage only, so that a query of a fabric reports its diagnostics once when a low-level weaver splits the pipeline. A query does not see the declarations that the later stages introduce. The compile-time pipeline still evaluates the replayed contributors in every stage (metalama/Metalama#2113).
- The reference walker descends into the implementations of members when `ReferenceKinds.NameOf` is requested, and it indexes a method group in a `nameof` expression as a reference to every method of the group. Before, a validator that requested only `NameOf` received no reference from a member body, and no validator received a `nameof` of a method. These changes are part of the release note of F1.
- `ISourceExpression.AsTypedConstant` of the `default` literal is the default value of the type of the expression. It was a string constant whose value was the text of the keyword.
- An existing method declared in a generic type is refused with LAMA1013, because the rewritten call would have to give the type arguments of its declaring type.
- The detection of a call omitted by `[Conditional]` reads the `#define` and `#undef` directives of the syntax tree and ignores those in an inactive region of an `#if` directive.
- The contributor kinds of the engine are `InterceptorsContributorKinds.Registration`, `RegistrationInstance` and `DesignTimeRegistration`, instead of the names of section 9.4.1. The last two are project-local.
- The message of LAMA1005 says that the template provider of the registration does not contain the template, instead of naming the type of the provider as in the catalog of section 9.11, because the type of a `TemplateProvider` is not public.
- An unsupported default value of an omitted argument is reported with LAMA1012 only when the existing method receives the argument. An interceptor that drops the argument is not affected.
- The change of `AspectTestRunner` goes beyond item 9 of section 11.3: the check is also skipped when the output compilation is disabled, and the result records whether the runner attempted to execute the program. Its tests are in `AspectTestRunnerProgramOutputTests`, with other names than in section 12.8.

# Test plan

> Part of the [call-site interceptors design](README.md). Previous: [11-delivery-plan.md](11-delivery-plan.md) | Next: [13-documentation-plan.md](13-documentation-plan.md). Evidence prefixes and terms: [00-conventions.md](00-conventions.md).

## 12. Test plan

### 12.1 Principles

- Each open-source primitive is proven in the open-source repository, without Premium, through the in-repository proof of concept of interceptors (section [12.5](#125-in-repository-proof-of-concept-of-interceptors), RC45). The proof-of-concept tests ship in the same pull request as the primitive.
- Premium tests focus on premium logic: the context model, the providers, conflicts, grouping and signature derivation. The cross-repository and cross-solution tests (premium standalone scenarios, the corpus of section [12.9](#129-semantic-equivalence-corpus-test)) are a smoke layer, not the main proof of open-source behavior.
- Every aspect test is run before its expected output is committed. The expected output is read, not copied without review.
- Tests never use delays. Synchronization uses `TaskCompletionSource`, barriers and custom synchronization contexts.
- Engine assertions use `Invariant.Assert`.
- Every new test project has a `.5.0.0` variant that recompiles the same sources.
- Test projects are built in continuous-integration mode before every push.

### 12.3 Open-source linker tests (`Metalama.Framework.Tests.LinkerTests`)

The runner (TST26 `Metalama.Framework.Tests.LinkerTests\Runner\LinkerTestInputBuilder.cs`) gets three elements, following the existing pseudo-attribute conventions. An attribute cannot be placed on an expression, so each attribute is placed on the member that contains the call sites and selects them by the invoked name.

- `[PseudoRedirectInvocations( "Bar", "Interceptors.Bar", ReceiverMode = "FirstArgument" )]` and `[PseudoRedirectAwaits( "Interceptors.Await", ConfigureAwait = false )]` on a member.
- `[PseudoSynthesizedMethod( "TestAspect" )]` on a method: the method is removed and injected through a test `SynthesizedMethodTransformation` whose body is copied from the declaration.
- `[PseudoLocalFunction( nameof(Host), "TestAspect" )]` on a method: the method is removed and injected as a local function into `Host`.
- `[PseudoRedirectMethodReferences( "Bar", "Interceptors.Bar", ReceiverMode = "Drop" )]` on a member: every method group named `Bar` in the member that is converted to a delegate or to a function pointer is redirected. `WrapperDelegateType` is taken from the converted type of the site.
- `[PseudoRedirectAccessors( "Quantity", Get = "Interceptors.GetQuantity", Set = "Interceptors.SetQuantity", ReceiverMode = "FirstArgument" )]` on a member: every use of the property or event named `Quantity` in the member is redirected, with `Add` and `Remove` for events. The context and the need for a temporary are computed from the semantic model, as the premium engine does.

New overload `LinkerTestInputBuilder.ToAspectLinkerInput( CompilationModel, ExtensionLinkerInput )`.

### 12.5 In-repository proof of concept of interceptors

The open-source repository contains a test-only, minimal implementation of interceptors (RC45). It is not a product and it is never packed. Its purpose is to exercise every open-source primitive of section [10](10a-oss-bridge-hook-factory.md#10-open-source-extension-points) end to end inside the open-source repository, so that the design does not rely primarily on cross-repository or cross-solution tests. It needs no interception context model, no grouping heuristics and no template selection logic. It replaces the test verbs of the earlier test-only extension, which called each primitive separately.

EXISTING loading mechanisms:

- Aspect tests load extensions from the `MetalamaExtensionAssembly` items of the test project, which `Metalama.Testing.AspectTesting.targets` writes to `extensions.txt` and the test executor passes as `TestContextOptions.ExtensionAssemblies` (TST27 `..\Metalama.Testing.AspectTesting\Metalama.Testing.AspectTesting.targets:133-160`; `..\Metalama.Testing.AspectTesting\XunitFramework\TestExecutor.cs:300-302, 331`). Compile-time assemblies are passed the same way from `MetalamaCompileTimeAssembly` items (line 301). `Metalama.Framework.Tests.AspectTests` already loads two in-repository extensions, `Metalama.Extensions.HtmlWriter` and `Metalama.Extensions.DiffEngine`, by importing their `MetalamaExtensionAssemblies.props` (TST27 `Metalama.Framework.Tests.AspectTests\Metalama.Framework.Tests.AspectTests.csproj:86-88`).
- Unit tests register extension types with `UnitTestClass.ConfigureExtensions`, and `TestExtensionLoader` returns them as `ExportExtensionAttribute` entries (TST27 `..\Metalama.Testing.UnitTesting\UnitTestClass.cs:128, 203-215`; `..\Metalama.Testing.UnitTesting\TestExtensionLoader.cs:16-37`).
- A compile-time plug-in cannot provide a `PipelineExtension` (ENG27 `Pipeline\AspectPipeline.cs:239-243, 489-506`). `Metalama.Framework.Tests.AspectTests` has `InternalsVisibleTo` access to `Metalama.Framework` (FW27 `Metalama.Framework.csproj:20-21`) and to the engine (ENG27 `Metalama.Framework.Engine.csproj:46`), so tests there could hide a missing public API.

Test-only API:

```csharp
namespace Metalama.Framework.Tests.ExtensionPoints;

/// <summary>Selects the placement and the receiver mapping of the method that the proof of concept generates.</summary>
[CompileTime]
public enum TestShape
{
    StaticInGeneratedClass,        // R0, R1 or R1x in the generated static class.
    StaticInCallingType,           // R0 or R1 in the calling type.
    InstanceOnReceiver,            // R2: ProceedBinding.InvokeOnThis, CallSiteReceiverMode.MemberOfReceiver.
    InstanceInCallingType,         // R3, or R4 for a base call.
    LocalFunction
}

[CompileTime]
public static class TestInterceptionExtensions
{
    /// <summary>
    /// Intercepts every call, method reference and await of the methods named <paramref name="methodName"/> in the scope of
    /// <paramref name="adviser"/> with the template <paramref name="template"/> of the current template provider.
    /// </summary>
    public static void TestInterceptCalls<T>( this IAdviser<T> adviser, string methodName, string template, TestShape shape = TestShape.StaticInGeneratedClass )
        where T : class, IDeclaration;

    /// <summary>Redirects every call and method reference of the methods named <paramref name="methodName"/> to an existing method.</summary>
    public static void TestRedirectCalls<T>( this IAdviser<T> adviser, string methodName, IMethod replacement )
        where T : class, IDeclaration;

    /// <summary>
    /// Intercepts every use of the accessor <paramref name="accessorKind"/> of the properties or events named
    /// <paramref name="memberName"/> with the template <paramref name="template"/>.
    /// </summary>
    public static void TestInterceptAccessors<T>( this IAdviser<T> adviser, string memberName, MethodKind accessorKind, string template, TestShape shape = TestShape.StaticInGeneratedClass )
        where T : class, IDeclaration;

    // The same three verbs on IQuery<T>, for fabrics, and TestInterceptAwaits( string template ).
}

[CompileTime]
public sealed class TestInterceptionInfo : IMetaExtension
```

```csharp
public sealed class InterceptCallsAttribute : TypeAspect
{
    private readonly string _methodName;
    private readonly TestShape _shape;

    public InterceptCallsAttribute( string methodName, TestShape shape = TestShape.StaticInGeneratedClass )
    {
        this._methodName = methodName;
        this._shape = shape;
    }

    public override void BuildAspect( IAspectBuilder<INamedType> builder )
        => builder.TestInterceptCalls( this._methodName, nameof(this.Log), this._shape );

    [Template]
    private dynamic? Log()
    {
        Console.WriteLine( $"Intercepted {meta.GetExtension<TestInterceptionInfo>().MethodName}." );

        return meta.Proceed();
```

Behavior of `TestInterceptorsPipelineExtension`, which uses every primitive and nothing else:

1. Registration. The verbs call `AdviserExtensibility.GetExtensionContext` and capture an `ExtensionContributionOrigin`, or create a query context for a fabric (section [10.2](10a-oss-bridge-hook-factory.md#102-adviser-bridge-b2a)). The contributor kind is project-local (section [10.8.1](10c-oss-reference-graph-design-time.md#1081-contributorkindisprojectlocal)).
2. Index. `GetSourceIndexRequirements` returns, in the source stage only, one requirement per registered method name for `ReferenceKinds.Invocation` and `ReferenceKinds.Default`, one per registered property or event name for `ReferenceKinds.Default` and `ReferenceKinds.Assignment`, one `Await` requirement for an await registration, and the declaration roots when all its scopes are types or members (section [10.7.5](10c-oss-reference-graph-design-time.md#1075-shared-index-of-source-references)).
3. Hook. `ExecuteTransformingContributorsAsync` returns immediately unless `IsSourceStage` is true (section [10.3](10a-oss-bridge-hook-factory.md#103-transforming-pipeline-hook-b2b)). It reads the shared index, and binds each reference to an invocation, a method group (section [6.2.10](06a-call-site-model.md#6210-method-reference-sites), without limitations), an accessor site (section [6.2.11](06a-call-site-model.md#6211-accessor-sites), without limitations) or an await.
4. Grouping. One synthesized method per registration, shape and target method, in deterministic order. The proof of concept rejects the sites whose signatures differ within such a group with a test diagnostic, because it has no grouping heuristics.
5. Emission. `DeclareStaticClass` for `StaticInGeneratedClass`; `DeclareMethod` with the template, the proceed binding of the shape (`InvokeStatic`, `InvokeOnParameter`, `InvokeOnThis`, `InvokeOnBase`, `AwaitParameter`) and `MetaExtensions = [ new TestInterceptionInfo( ... ) ]`; then `RedirectInvocation`, `RedirectAwait`, `RedirectMethodReference` or `RedirectAccessor` for each site, with the receiver mode of the shape (section [10.4](10a-oss-bridge-hook-factory.md#104-extension-transformation-factory-b2c)).
6. Design time. `AnalyzeSemanticModel` reports a hidden test diagnostic for each matched site, from the project-local registrations of the design-time pipeline result.

The proof of concept grows with the milestones. In M0, it has only `TestRedirectCalls`, because `DeclareMethod` ships in M2. `TestInterceptCalls` and the shapes of `TestShape` arrive with the milestone that adds their primitives: static interceptors in type placements, `InstanceInCallingType`, meta extensions and `TestInterceptAccessors` for sites with one accessor use in M2, `InstanceOnReceiver`, base calls and compound accessor sites in M3, `LocalFunction` in M4, and `TestInterceptAwaits` in M5.

The premium tests that exercise the linker or the template engine are limited to the scenarios that need the premium context model.

### 12.8 Premium runtime-execution tests (`Runtime/`)

EXISTING: the aspect test runner executes the method of the `Program` class that the `MainMethod` option names (default `Main`; TST27 `..\Metalama.Testing.AspectTesting\AspectTestRunner.cs:392`), awaits it when it returns a `Task`, and compares the console output with `.t.txt` (lines 337-357, 384-450). When no such method exists, nothing runs and the expected output is ignored (lines 302-307, 502-504). The premium project therefore sets `"MainMethod": "TestMain"` (section [12.7](#127-premium-aspect-tests-metalamaextensionsinterceptorsaspecttests-and-500)), and an open-source change of M0 makes the runner fail a test that has a non-empty `.t.txt` but whose program was not executed.

Method: each test executes the same operation twice in one program: once inside the interceptor scope, and once in a control method outside the scope. The program prints one line per observation for each path, and the expected output shows that both lines are equal. An awaited operation completes from another thread through a `TaskCompletionSource` completed only after the awaiting function has returned. A test-local `PumpSynchronizationContext` runs a message loop on a dedicated thread, and a recording synchronization context observes the resumption context.

```csharp
// Runtime/Await_ConfigureAwaitFalse_NotCaptured.cs (run-time part, sketch)
internal static class Program
{
    public static async Task TestMain()
    {
        Console.WriteLine( $"intercepted: {await Probe.InScopeAsync()}" );
        Console.WriteLine( $"control:     {await Probe.OutOfScopeAsync()}" );
    }
}
```

### 12.9 Semantic-equivalence corpus test

A syntactic rewrite reproduces many binding rules, which hand-written tests cannot combine exhaustively.

- A pass-through fabric registers, for every method use of the compilation (calls and method references converted to delegates or to function pointers), a template interceptor whose body is only `return meta.Proceed();`. The fabric uses a type predicate that accepts every type, with the names of the methods that the corpus calls. From M3, it also registers the four accessor kinds for the properties and events of the corpus. The interceptor returns `InterceptorResult.Skip` when `context.NonInterceptableReason` is not null. From M5, the fabric also registers an await interceptor with the same body, which returns `InterceptorResult.Skip` for await expressions whose resumption is `Unknown`.
- The corpus is built with that fabric, and its own unit tests are run. They must pass as they do without the fabric, and the build must report no new warning.
- Continuous-integration corpus: one in-process project with many asynchronous and generic call sites, LINQ method groups, event subscriptions, and an ASP.NET Core minimal API whose handlers are method groups with `[FromServices]` parameters, stored as the premium standalone scenario `InterceptorsPassThroughCorpus`. The invocation part is required for the M2 exit, and the await part for the M5 exit.
- Large corpus (required before the stable release): the nopCommerce clone that the open-source benchmark uses (TST27 `Metalama.Framework.Tests.Benchmarks\README.md`), run manually or on a scheduled build.

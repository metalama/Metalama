## Summary

1. Stable Roslyn packages on nuget.org are 5.0.0 (2025-11-18), 5.3.0 (2026-03-10), 5.6.0 (2026-07-02) and 5.9.0 (2026-08-17); there is no 5.10, 5.11 or 5.12 (flat-container index of `Microsoft.CodeAnalysis.CSharp`). Roslyn keeps public release branches only for 18.0 and 18.3 (`git ls-remote`); 5.9.0 was built from the internal branch `release/insiders` at commit `35d9211b` (present on `main`, dated 2026-07-01), eight days after `main` was bumped to 5.10 (2026-06-29). By that cadence the next stable is 5.12, the compiler of Visual Studio 18.12 and of the .NET 11 SDK; its November 2026 date is an inference from the cadence, not a published fact.
2. In 5.9.0 stable, and therefore in the consumed `5.10.0-1.26365.3` (a `main` build of 2026-07-15; the `PublicAPI.Unshipped.txt` files are byte-identical at `35d9211b` and at the 2026-07-28 end of the 5.10 window, and the file histories show no API commit between 2026-06-24 and 2026-07-31), the union, closed-class, `with(...)`, labeled-break and pre-compilation API exists but is `[RSEXPERIMENTAL006]` or `[RSEXPERIMENTAL007]`, `Syntax.xml` carries `ExperimentalUrl` on `UnionDeclarationSyntax`, `WithElementSyntax`, the `Name` field of `BreakStatementSyntax` and `ContinueStatementSyntax`, and `UnsafeExpressionSyntax`, `LanguageVersion.CSharp15` does not exist, `MessageID.RequiredVersion` returns `Preview` for `IDS_FeatureCollectionExpressionArguments`, `IDS_FeatureUnions`, `IDS_FeatureStaticMembersInInterfaces`, `IDS_FeatureClosedClasses`, `IDS_FeatureLabeledBreakContinue` and `IDS_FeatureExtensionIndexers`, and `Default`/`Latest`/`LatestMajor` map to `CSharp14`. The 5.9.0 XML documentation confirms it: `ITypeSymbol.IsUnion`, `IsClosed`, `GetClosedDerivedTypeInfo`, `ClosedDerivedTypeInfo`, `UnionDeclarationSyntax`, `WithElementSyntax`, `SyntaxKind.ClosedKeyword`, `RegisterPreCompilationSourceOutput`, `OperationKind.CollectionExpressionElementsPlaceholder` and `ReduceExtensionMember` are documented; `LanguageVersion.CSharp15`, `ITypeSymbol.UnionCaseTypes` and `INamedTypeSymbol.TypeLayout` are not (the string `CSharp15` in the assembly is only the `InternalsVisibleTo` name `Microsoft.CodeAnalysis.CSharp.CSharp15.UnitTests`, and the `UnionCaseTypes` strings are the internal names `get_UnionCaseTypesNoUseSiteDiagnostics`, `get_ERR_MissingUnionCaseTypes` and a local-function closure, not a public member).
3. `LanguageVersion.CSharp15 = 1500`, the switch of `RequiredVersion` to `CSharp15`, the `Default`/`Latest`/`LatestMajor` mapping to `CSharp15` and the removal of the `ExperimentalUrl` and `[RSEXPERIMENTAL006]` markers all come from one commit, "Add C# 15 language version (#84799)" of 2026-08-11 (the only commit to `LanguageVersion.cs` since 2025-08-07 and the only commit to `Syntax.xml` after 2026-06-24); `ITypeSymbol.UnionCaseTypes` (2026-07-31) and `TypeLayout` (2026-08-19) are also later than the consumed build. The FACTS statement "MapSpecifiedToEffectiveVersion maps Default/Latest/LatestMajor to CSharp15 on main" is true of `main` since 2026-08-11 and false of the consumed build and of 5.9.0.
4. The .NET SDK 11.0.100-preview.5 tag (2026-06-01) carried Roslyn 5.8.0; no tag exists yet for Visual Studio 18.8 final, 18.9 or 18.10. Metalama's `Roslyn.5.10.0` variant therefore targets an API in which C# 15 is preview-only and the new syntax API is experimental; the first package expected to contain `CSharp15` and the non-experimental union API is 5.12.
5. No enum that Metalama switches on gains a value in 5.10 except `SyntaxKind` (`WithElement` 9081, `UnionDeclaration` 9082, `UnionKeyword` 8452, `ClosedKeyword` 8453, `SafeKeyword` 8454, `UnsafeExpression` 8769) and `OperationKind` (`CollectionExpressionElementsPlaceholder` 129). `TypeKind`, `SymbolKind`, `MethodKind` and `Accessibility` are unchanged; a union has `TypeKind.Struct` (`EnumConversions.ToTypeKind` maps `DeclarationKind.Union` to `TypeKind.Struct`).
6. Unions surface as `ITypeSymbol.IsUnion` (5.10, experimental) and `ITypeSymbol.UnionCaseTypes` (5.11); closed classes as `ITypeSymbol.IsClosed` and `ITypeSymbol.GetClosedDerivedTypeInfo(CancellationToken)` returning the new struct `ClosedDerivedTypeInfo`. Both are on `ITypeSymbol`; `INamedTypeSymbol` only gains `TypeLayout` (5.11).
7. Two syntax node types are new (`UnionDeclarationSyntax : TypeDeclarationSyntax` with a `ParameterList`, `WithElementSyntax : CollectionElementSyntax`), and `BreakStatementSyntax`/`ContinueStatementSyntax` gain an optional `Name`. Extension indexers and closed classes add no node. No IOperation type is added for labeled break/continue (the existing `IBranchOperation.Target` is used).
8. "Pre-compilation registration" is `IncrementalGeneratorInitializationContext.RegisterPreCompilationSourceOutput` (`[RSEXPERIMENTAL007]`, in 5.10), a generator phase between post-initialization and source outputs, documented in `docs/features/pre-compilation-source-outputs.md`; it is not an analyzer API.
9. `IDS_FeatureStaticMembersInInterfaces` has no csharplang proposal; it is Roslyn PR #83097 (merged 2026-04-10): non-virtual static methods with bodies, static fields and static field-like events in interfaces compile on runtimes without default interface implementation support (for example `net472`), gated on the feature version.
10. Local inventory: 326 switch statements or expressions over the five enums in `Metalama.Framework/src` (SyntaxKind 156, SymbolKind 112, MethodKind 48, TypeKind 17, OperationKind 0; a switch over a tuple is counted once per enum), 146 entries with a throwing default arm (12 TypeKind, 38 SymbolKind, 22 MethodKind, 74 SyntaxKind), and 118 visitor classes (49 `SafeSyntaxRewriter`, 25 `SafeSyntaxWalker`, 12 `SymbolVisitor`, 11 `CSharpSyntaxWalker`, 8 `SafeSyntaxVisitor`, 7 `CSharpSyntaxRewriter`, 5 `CSharpSyntaxVisitor`, 1 `MetaSyntaxRewriter`, no `OperationVisitor` or `OperationWalker`).

### Attribute changes between the 5.10 snap and the 5.11 snap

Every `[RSEXPERIMENTAL006]` prefix on the union, closed-class, collection-argument and labeled-break API listed in the first table was removed at the 5.11 snap (the lines reappear without a prefix). `Syntax.xml` at the 5.10 snap carries `ExperimentalUrl` on `UnionDeclarationSyntax` (issue 82567), `WithElementSyntax` (issue 82210), the `Name` field of `BreakStatementSyntax` and `ContinueStatementSyntax` (issue 83266) and `UnsafeExpressionSyntax` (issue 82789); at the 5.11 snap and on main only `UnsafeExpressionSyntax` keeps it. The consumed `eng/src/GenerateMetaSyntaxRewriter/Syntax-5.10.0.xml` has the same five markers as the 5.10 snap, so the current generator output matches the consumed preview and the stable 5.9.0, and a move to a build of `main` after 2026-08-11 (5.12 in practice) will make the generator emit code for the three nodes. The stable 5.9.0 assemblies confirm the markers: at commit `35d9211b` the Core `PublicAPI.Unshipped.txt` has 15 `[RSEXPERIMENTAL006]` and 7 `[RSEXPERIMENTAL007]` lines and the CSharp file has 89 `[RSEXPERIMENTAL006]` lines, both files byte-identical to the 5.10 window, and `Syntax.xml` at that commit has the same five `ExperimentalUrl` markers as `Syntax-5.10.0.xml`.

### Verified unchanged between 5.0 and main

- `Microsoft.CodeAnalysis.TypeKind`: 16 values, highest `Extension = 14`; no `Union` value. `EnumConversions.ToTypeKind` (`src/Compilers/CSharp/Portable/Symbols/EnumConversions.cs` lines 35-38) maps `DeclarationKind.Struct`, `DeclarationKind.Union` and `DeclarationKind.RecordStruct` to `TypeKind.Struct`; `SourceMemberContainerSymbol.MakeModifiers` treats a union declaration inside `case TypeKind.Struct`.
- `Microsoft.CodeAnalysis.SymbolKind` (highest `FunctionPointerType = 20`), `Microsoft.CodeAnalysis.MethodKind` (highest `FunctionPointerSignature = 18`), `Microsoft.CodeAnalysis.Accessibility`, `ISymbol.DeclaredAccessibility`, `IMethodSymbol.MethodKind`: no change.
- `IPropertySymbol`: only `ReduceExtensionMember` (see above). Extension indexers are `IPropertySymbol` instances with `IsIndexer == true` declared on an `INamedTypeSymbol` with `IsExtension == true` (`TypeKind.Extension`), using the 5.0 members `ExtensionParameter`, `ExtensionGroupingName`, `ExtensionMarkerName` and `AssociatedExtensionImplementation`.
- `INamedTypeSymbol`: only `TypeLayout` (5.11). No `IsUnion`, `UnionCaseTypes` or `IsClosed` on `INamedTypeSymbol`; they are on `ITypeSymbol`.

## Feature semantics

### Unions

Proposal: https://github.com/dotnet/csharplang/blob/main/proposals/csharp-15.0/unions.md (champion issue dotnet/csharplang#9662). Roslyn feature branch `features/Unions`, tracking issue dotnet/roslyn#81074; merged into `main` on 2026-03-05.

- Syntax: `attributes? struct_modifier* 'partial'? 'union' identifier type_parameter_list? '(' case_types ')' struct_interfaces? type_parameter_constraints_clause* ( '{' struct_member_declaration* '}' | ';' )`. Roslyn: `UnionDeclarationSyntax` (kind `UnionDeclaration`), `DeclarationKind.Union`, `TypeKind.Struct`; the case types are the `ParameterList`.
- Lowering: a struct with the synthesized `[System.Runtime.CompilerServices.Union]` attribute (unless the source already applies it, `SourceNamedTypeSymbol.ShouldApplyUnionAttribute`), implementing `System.Runtime.CompilerServices.IUnion`, with a synthesized `public object? Value { get; }` (`SynthesizedUnionValuePropertySymbol`) and one public constructor per case type (`SynthesizedUnionCtor`); optional user-declared `HasValue` and `TryGetValue<T>(out T)` members avoid boxing. A union conversion (`Conversion.IsUnion`) is an implicit conversion from a case type that calls the creation member; it is not allowed in expression trees (CS9369).
- Restrictions: allowed modifiers are those of structs including `partial`, `readonly`, `unsafe`/`safe`, but not `ref` (`SourceMemberContainerSymbol.MakeModifiers`); nesting and generics are allowed; at least one case type (CS9370); no instance fields, auto-properties or field-like events (CS9373); no explicitly declared public single-parameter constructor (CS9374); explicit constructors must chain with `this(...)` (CS9375); a `union` declaration cannot use a member provider interface (CS9387); a non-declared union type (attribute-marked) needs at least one creation member (CS9385) and a public `Value` getter of type `object` (CS9386). The proposal states that every union member must be public; it says nothing about `InternalsVisibleTo`.
- Diagnostics: exhaustiveness reuses CS8509 (switch expression not exhaustive) and CS8655 (null input not handled); a switch that handles every case type is exhaustive without a fallback; CS9372 when a pattern cannot handle the union `Value`; the feature version is checked through `IDS_FeatureUnions` (`Preview` in 5.10, `CSharp15` from 5.11).

### Closed hierarchies

Proposal: https://github.com/dotnet/csharplang/blob/main/proposals/csharp-15.0/closed-hierarchies.md (champion issue dotnet/csharplang#9499). Roslyn feature branch `features/closed-class`, tracking issue dotnet/roslyn#81039; public API merged 2026-06-17 (#84045).

- Syntax: `closed` as a contextual modifier on classes only (`SyntaxKind.ClosedKeyword` 8453 in the `Modifiers` list of `ClassDeclarationSyntax`; no new node). A closed class is implicitly abstract; `sealed` or `static` is an error (CS9381) and an explicit `abstract` is an error (CS9384); a type or alias cannot be named `closed` (CS9380). Closed enums are a separate proposal (https://github.com/dotnet/csharplang/blob/main/proposals/closed-enums.md, champion dotnet/csharplang#9011) without a version target and without any implementation in Roslyn `main` (no error code, no `MessageID`).
- Lowering: `SourceNamedTypeSymbol` (lines 1805-1829 on main) synthesizes `[System.Runtime.CompilerServices.IsClosedType(DerivedTypes = new Type[] { typeof(D1), typeof(D2<>) })]` on the closed class, listing `CandidateClosedSubtypeDefinitions` as unbound generic definitions; `DerivedTypes` must be an instance `Type[]` property with public get and set accessors (CS9395). The proposal also specifies `[CompilerFeatureRequired("ClosedClasses")]` on the constructors; this was not verified in source. The public API is `ITypeSymbol.IsClosed` and `ITypeSymbol.GetClosedDerivedTypeInfo`.
- Restrictions: "cannot use a closed type '{1}' from another assembly as a base type" (CS9382, `ERR_ClosedBaseTypeBaseFromOtherAssembly`); the proposal also requires the same module; a generic derived class must reference every type parameter in its base type (CS9383, `ERR_UnderspecifiedClosedSubtype`); nesting is not required; `partial` is not discussed by the proposal.
- Diagnostics: `InternalsVisibleTo` does not lift the same-assembly rule, because the rule is on the assembly and not on accessibility, and the proposal does not mention friend assemblies. Exhaustiveness: a switch that handles every direct derived type exhausts the closed class (otherwise the existing CS8509 family); a case for the closed base after all derived types is an unreachable-case error; a closed class without subtypes is not exhausted by an empty switch; a type parameter constrained to a closed class is treated like the closed class.

### Labeled break and continue

Proposal: https://github.com/dotnet/csharplang/blob/main/proposals/csharp-15.0/labeled-break-continue.md (champion issue dotnet/csharplang#9875). Roslyn feature branch `features/labeled-break-and-continue`, merged through dotnet/roslyn#84271 (parsing in #83197, 2026-04-23).

- Syntax: `break identifier? ;` and `continue identifier? ;`; the label is an ordinary `labeled_statement` whose statement is a `switch_statement` or an `iteration_statement`. Roslyn: the optional `Name` field (`IdentifierNameSyntax`) on `BreakStatementSyntax` and `ContinueStatementSyntax`; no new `SyntaxKind`.
- Lowering: the binder resolves the label to the enclosing loop's existing break or continue label symbol and emits the ordinary bound break or continue statement (`Binder_Statements.cs` lines 2960-2991); there is no new bound node, no new IL pattern, and no new IOperation (an `IBranchOperation` with `BranchKind.Break` or `Continue`).
- Restrictions: only a `switch` or an iteration statement can be targeted; the nearest enclosing statement labeled with that identifier is chosen; only the statement directly nested under the label receives it; a labeled `continue` cannot target a `switch`; a `finally` block cannot be left.
- Diagnostics: CS9393 `ERR_NoBreakId` ("No enclosing loop or switch statement with the label '{0}' out of which to break"), CS9394 `ERR_NoContinueId`; the feature version is checked through `IDS_FeatureLabeledBreakContinue` at the location of the name. Nothing relates to `InternalsVisibleTo` or exhaustiveness.

### Collection expression arguments

Proposal: https://github.com/dotnet/csharplang/blob/main/proposals/csharp-15.0/collection-expression-arguments.md (champion issue dotnet/csharplang#8887). Roslyn feature branch `features/collection-expression-arguments`, tracking issue dotnet/roslyn#80613 (parsing merged 2025-10-03, IOperation 2025-12-04).

- Syntax: `collection_element : expression_element | spread_element | with_element`, `with_element : 'with' argument_list`; an element that starts with `with (` is always a `with_element`; it must be the first element. Roslyn: `WithElementSyntax` (kind `WithElement`), `ArgumentList : ArgumentListSyntax`.
- Lowering: for a class or struct target the arguments select an accessible instance constructor by overload resolution; for a `CollectionBuilder` target they select a create method whose last parameter is the `ReadOnlySpan<T>` of elements (the arguments are prepended); for mutable interface targets the candidate signatures are those of `List<T>()` and `List<T>(int)` (plus comparer overloads for dictionary interfaces). IOperation: `ICollectionExpressionOperation.ConstructArguments` and the placeholder operation kind 129.
- Restrictions: not first (CS9354), unsupported target type such as arrays and spans (CS9355), dynamic arguments (CS9356), non-empty `with()` for a read-only interface (CS9357), wrong argument count for the create method (CS9359). The presence of `with(...)` affects whether the collection conversion exists; the argument values do not.
- Diagnostics: none related to `InternalsVisibleTo` or exhaustiveness.

### Extension indexers

Proposal: https://github.com/dotnet/csharplang/blob/main/proposals/csharp-15.0/extension-indexers.md (champion issue dotnet/csharplang#9856; LDM decisions 2026-02-02 to 2026-04-07). Roslyn feature branch `features/extensions`, tracking issue dotnet/roslyn#81505.

- Syntax: an `indexer_declaration` (`this[...]`) inside an `extension(T receiver) { }` block; instance members only, so the block must name its receiver parameter. Roslyn reuses `IndexerDeclarationSyntax` inside `ExtensionBlockDeclarationSyntax`; no new node, kind or symbol API.
- Lowering: static implementation methods `get_Item`/`set_Item` with the receiver prepended to the parameter list, emitted in the grouping type marked `[Extension]` and `[DefaultMember("Item")]`, plus the marker type; the indexer appears as an `IPropertySymbol` (`IsIndexer`) on the extension type (`TypeKind.Extension`) and reduces through `IPropertySymbol.ReduceExtensionMember`.
- Restrictions: no `abstract`, `virtual`, `override`, `new`, `sealed`, `partial` or `protected` modifiers and no `init` accessor; every type parameter of the block must be inferable from the parameters; no extension indexers on strings or arrays (LDM 2026-04-07); not allowed in expression trees; never considered on a `base` receiver; element access binds instance indexers first, then implicit `Index`/`Range` indexers, then extension indexers, then implicit extension indexers.
- Diagnostics: an ambiguity between applicable extension indexers is a compile-time error; the feature version is checked through `IDS_FeatureExtensionIndexers`. Nothing relates to `InternalsVisibleTo` or exhaustiveness.

### Static members in interfaces without runtime support for default interface implementation

There is no csharplang proposal. The `docs/Language Feature Status.md` row is "Non-virtual static interface members without DIM runtime support", branch `main`, state "C# 15" linking to Roslyn PR https://github.com/dotnet/roslyn/pull/83097 ("Enable declaration and consumption of non-virtual static members in interfaces regardless of runtime support for Default Interface Implementations", merged 2026-04-10 into `features/Unions`, developer AlekseyTs, no LDM champion). The resource string of `IDS_FeatureStaticMembersInInterfaces` is "static members in interfaces".

- Syntax: none new.
- Lowering: none new; the members are ordinary static interface members.
- Restrictions: when `ContainingAssembly.RuntimeSupportsDefaultInterfaceImplementation` is false (for example a `net472` or `netstandard2.0` target), a non-virtual static method with a body or an `extern` body (`SourceMemberMethodSymbol.cs` lines 1086-1091), a static field (`SourceMemberFieldSymbol.cs` lines 404-414) or a static field-like event (`SourceFieldLikeEventSymbol.cs`) declared in an interface now goes through `ReportLackOfRuntimeSupportForStaticMembersInInterfaces`, which reports the feature-version check instead of `ERR_RuntimeDoesNotSupportDefaultInterfaceImplementation`; protected, protected internal and private protected members still report `ERR_RuntimeDoesNotSupportProtectedAccessForInterfaceMember`. Instance members with bodies and static virtual or abstract members keep their previous errors.
- Diagnostics: the feature check (`Preview` in 5.10, `CSharp15` from 5.11). Relevance: the union feature uses static interface members, and Metalama's Desktop flavour (`net472`) will accept such declarations in compile-time and user code once the language version is C# 15.

### Pre-compilation source outputs (the "pre-compilation registration" of the handoff)

Document: `docs/features/pre-compilation-source-outputs.md` on `main`; API merged 2026-05-20 (#83088), present in 5.10 as `[RSEXPERIMENTAL007]`. `RegisterPreCompilationSourceOutput` is a new incremental generator phase that runs after `RegisterPostInitializationOutput` and before `RegisterSourceOutput`; its sources are added to the initial compilation, so every generator's standard phase and semantic model sees them. Its input providers must not depend on the compilation or on syntax nodes (additional files, parse options and analyzer config options are allowed); reading a compilation-dependent value throws `InvalidOperationException` and puts the generator into an error state. `PreCompilationSourceProductionContext` exposes `AddSource` and `CancellationToken` only, with no diagnostic reporting. The stated use cases are Razor (removing an intermediate compilation) and cross-generator dependencies. It is not an analyzer API and it is not an alternative to `RegisterCompilationStartAction`.

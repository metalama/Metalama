# 03. Union types and closed hierarchies in the code model

Analysis of `develop/2027.0` (branch `topic/2027.0/26-09-03-update-eng-7e3j07`) on 2026-09-03. Every path below is relative to `/home/user/Metalama`. Facts marked "verified" were read in the code; facts marked "plausible" rest on the Roslyn `main` branch or on a csharplang proposal that the stable Roslyn 5.10 may still change. The facts of `FACTS.md` are not repeated here and are not contradicted.

## Summary

1. A C# 15 union lowers to a plain struct: Roslyn reports it as `TypeKind.Struct`, `IsRecord` false, with one synthesized public constructor per case type, a synthesized `Value` property and an implicit `IUnion` interface. No nested case type is synthesized; the case types are pre-existing types. The premise that a union case is a synthesized nested type is not what the C# 15 proposal or the Roslyn implementation say.
2. Because the union is a struct, every switch over `TypeKind`, `DeclarationKind`, `SymbolKind` and `MethodKind` in the engine already has an arm for it. No such switch crashes on a union or on a closed class. Adding a `TypeKind.Union` value would turn 17 of those switches into crashes or silent exclusions, so the recommendation is an `INamedType.IsUnion` flag, following the precedent of `IsRecord` (`TypeKind.RecordClass` and `RecordStruct` are obsolete).
3. The breakage is in the syntax layer: `SyntaxKind.UnionDeclaration` is absent from 12 hand-written kind lists and 20 syntax visitors override `VisitClassDeclaration`, `VisitStructDeclaration` and `VisitRecordDeclaration` but not `VisitUnionDeclaration`. The consequences range from a wrong `LAMA0048` diagnostic (`IsPartial` is false for a `partial union`), to a design-time partial declaration emitted as `partial struct` instead of `partial union`, to an assertion in `FindMemberDeclaration` for a union declared in the global namespace.
4. `closed` is a modifier on classes and record classes only. Roslyn adds the `Abstract` flag to a closed class, so the code model reports `IsAbstract` true and `IsSealed` false, which is semantically correct today. The only work is to expose `IsClosed` on `INamedType` and `INamedTypeBuilder`, and to make `ModifierHelper` emit `closed` rather than `abstract` for an introduced closed class.
5. Identity and serialization are unaffected: a union is a named type with a `T:` documentation id, its synthesized members are ordinary symbols with `M:` and `P:` ids, and case types are ordinary types.
6. Every engine change that touches `UnionDeclarationSyntax`, `SyntaxKind.UnionDeclaration`, `ClosedKeyword`, `ITypeSymbol.IsUnion`, `UnionCaseTypes` or `IsClosed` does not compile in the `Roslyn.5.0.0` variant, and the current policy is that no production source branches on `ROSLYN_5_10_0_OR_GREATER`. That policy decision gates all findings below.

## Proposal facts

### Unions (`proposals/csharp-15.0/unions.md`)

- Section "Union types": "Any class or struct type with a `System.Runtime.CompilerServices.UnionAttribute` attribute is considered a *union type*". The attribute is declared as `[AttributeUsage(Class | Struct, AllowMultiple = false)] public class UnionAttribute : Attribute;`. The interface `IUnion` has a single member `object? Value { get; }`; "Unions generated by the compiler implement this interface."
- Section "Union member providers": union members are found on the type itself, or on a nested interface named `IUnionMembers` when the type directly contains one.
- Section "Union declarations", grammar quoted verbatim:

  ```
  union_declaration
      : attributes? struct_modifier* 'partial'? 'union' identifier type_parameter_list?
        '(' case_types ')'  struct_interfaces? type_parameter_constraints_clause*
        (`{` struct_member_declaration* `}` | ';')
      ;
  case_types
      : type (',' type)*
      ;
  ```

  Partial unions are legal (`'partial'?`). A union may implement interfaces (`struct_interfaces?`). A union has no base type, because it is a struct. Members may be declared in the body (`struct_member_declaration*`). Case types are existing types written in the header ("The *case_types* can be any type that converts to `object`, e.g., interfaces, type parameters, nullable types and other unions"); no new type is declared by a union declaration.
- Section "Union declarations", lowering, quoted verbatim: "A union declaration is lowered to a struct declaration with the same attributes, modifiers, name, type parameters and constraints, implicit implementations of `IUnion`, a `public object? Value { get; }` auto-property, a public constructor for each of the *case_types*, any members in the union declaration's body." Nothing else is synthesized: no `Equals`, no `GetHashCode`, no `TryGet*` method. The optional `HasValue` and `TryGetValue` members of the "non-boxing access" pattern are user-written.
- Section "Union declarations", restrictions, quoted verbatim: "Instance fields, auto-properties or field-like events are not permitted. Explicitly declared public constructors with a single parameter are not permitted. Explicitly declared constructors must use a `this(...)` initializer to (directly or indirectly) delegate to one of the generated constructors."
- Section "Union conversions": an implicit conversion from each case type to the union, executed by calling the union constructor.
- Section "Union pattern matching", exhaustiveness: "A union type is assumed to be 'exhausted' by its case types. This means that a `switch` expression is exhaustive if it handles all of a union's case types."
- Nested case types: `proposals/case-declarations.md` is a separate, unscheduled proposal ("Grammar: TBD") that would let `case Open(float Percent);` inside "the body of a closed class, record or union" expand to a nested `public sealed record`. It is not in the `csharp-15.0` folder and not in the C# 15 feature list of `FACTS.md`. `proposals/standard-unions.md` describes library types `Union<T1, T2>` and is not language syntax.

Roslyn `main` implementation, read on 2026-09-03 (plausible for the stable 5.10):

- `src/Compilers/CSharp/Portable/Symbols/EnumConversions.cs`: `DeclarationKind.Union` maps to `TypeKind.Struct`. `src/Compilers/CSharp/Portable/Declarations/DeclarationKind.cs`: `SyntaxKind.UnionDeclaration` maps to `DeclarationKind.Union`.
- `SourceNamedTypeSymbol_Bases.cs`: for `DeclarationKind.Union` the well-known type `System.Runtime.CompilerServices.IUnion` is added as an implicitly implemented interface.
- `Symbols/Synthesized/SynthesizedUnionCtor.cs`: `internal sealed class SynthesizedUnionCtor : SynthesizedInstanceConstructor`, public, one parameter created by `SynthesizedParameterSymbol.Create(this, parameterType, ordinal: 0, RefKind.None, ParameterSymbol.ValueParameterName)`; `Locations` is overridden with the union location. It is implicitly declared and has no declaring syntax reference (base class behaviour, plausible).
- `Symbols/Synthesized/SynthesizedUnionValuePropertySymbol.cs`: `internal sealed class SynthesizedUnionValuePropertySymbol : SourcePropertySymbolBase`, constructed with the `TypeDeclarationSyntax` of the union, `IsImplicitlyDeclared => true`, type `object?`, getter only. Its declaring syntax is therefore the union declaration, as the `EqualityContract` property of a record has the record declaration as its syntax.
- `src/Compilers/Core/Portable/Symbols/ITypeSymbol.cs`: `bool IsUnion { get; }` and `ImmutableArray<ITypeSymbol> UnionCaseTypes { get; }`.
- `src/Compilers/CSharp/Test/Syntax/Parsing/UnionParsingTests.cs`: `union U1(E1);`, `union U1(E1, E2, E3);`, `[Attr1] public union U1<T1>(E1) : I1, I2 where T1 : class { public void M1() { } }` and `partial union U1(E1);` parse without diagnostics; the case list is a `ParameterListSyntax` whose `ParameterSyntax` nodes carry a type and no identifier.
- The grammar consumed by this repository, `eng/src/GenerateMetaSyntaxRewriter/Syntax-5.10.0.xml:1954-1975`, declares `UnionDeclarationSyntax : TypeDeclarationSyntax` with `AttributeLists`, `Modifiers`, `Keyword` (`UnionKeyword`), `Identifier`, optional `TypeParameterList`, optional `ParameterList`, optional `BaseList`, `ConstraintClauses`, optional braces, `Members` and optional `SemicolonToken`, marked `ExperimentalUrl`.

### Closed hierarchies (`proposals/csharp-15.0/closed-hierarchies.md`)

- Section "Syntax", quoted verbatim: "Allow `closed` as a modifier on classes. A `closed` class is implicitly abstract. Thus, it cannot also have a `sealed` or `static` modifier. It is an error to explicitly use an `abstract` modifier on a `closed` class." The examples include `public closed record class GateState`, so record classes are covered.
- Section "Same-assembly restriction", quoted verbatim: "If a class in one assembly is declared `closed` then it is an error to directly derive from it in another assembly... The same restriction applies to modules. A subtype of a `closed` type must be located within the same module as the base type." `InternalsVisibleTo` is not mentioned and grants nothing.
- Section "Type parameter restriction": a generic class that directly derives from a closed class must use all its type parameters in the base class specification.
- Section "Exhaustiveness in switches", quoted verbatim: "A `switch` expression that handles all of the direct descendants of a closed class will be considered to have exhausted that class." A derived class is not closed unless declared so; subtypes that cannot be used, constraints, the absence of subtypes and type parameters constrained to a closed type each have a subsection.
- Section "Lowering", quoted verbatim: "Closed classes are generated with an `IsClosedTypeAttribute` attribute, to allow them to be recognized by a consuming compiler." The attribute is `[AttributeUsage(AttributeTargets.Class, AllowMultiple = false, Inherited = false)] public sealed class IsClosedTypeAttribute : Attribute { }` in `System.Runtime.CompilerServices`. "This is accomplished by adding `[CompilerFeatureRequired("ClosedClasses")]` to all `constructor`s of closed classes." No modreq is used.
- Section "Optional features": "`Interface`s could also be allowed to be closed. The rules would be very similar." Structs and enums are not covered. Partial types are not addressed.
- Closed enums (`proposals/closed-enums.md`, in the root folder, not in `csharp-15.0`): a closed enum "must include a member with integral value 0", is "generated with a `Closed` attribute", and makes a switch over all members exhaustive. It is not in the C# 15 feature list of `FACTS.md` and is out of scope for 2027.0.

Roslyn `main` implementation (plausible for the stable 5.10):

- `SourceMemberContainerSymbol.cs`: `DeclarationModifiers.Closed` is allowed only under `case TypeKind.Class: case TypeKind.Submission:`; a closed class with `sealed` or `static` reports `ERR_ClosedSealedStatic`, with explicit `abstract` reports `ERR_ClosedExplicitlyAbstract`; then `if ((mods & DeclarationModifiers.Closed) != 0) mods |= DeclarationModifiers.Abstract;`. `IsClosed => HasFlag(DeclarationModifiers.Closed)` and `IsAbstract => HasFlag(DeclarationModifiers.Abstract)`. The modifiers of partial parts are merged with `result |= mods`, which is the rule of the C# standard §15.2.7 for `abstract`, `sealed` and `static` ("If one or more parts of a partial type declaration of a class include the `abstract` modifier, the class is abstract").
- `ITypeSymbol.cs`: `bool IsClosed { get; }` and `ClosedDerivedTypeInfo GetClosedDerivedTypeInfo(CancellationToken cancellationToken)`, which throws `InvalidOperationException` when the type is not closed.
- `AttributeDescription.cs` declares both `UnionAttribute` and `IsClosedTypeAttribute` in `System.Runtime.CompilerServices`.
- `Test/Syntax/Parsing/ClosedModifierParsingTests.cs`: `closed partial class C { }` and `closed partial record class C { }` parse; `partial closed class C { }` reports CS0267 because `partial` must immediately precede `class`. `Test/CSharp15/ClosedClassesTests.cs` has a test with two parts both written `closed partial class C1;`. No test where only one part carries `closed` was found by code search.
- Whether the July 2026 build `5.10.0-1.26365.3` consumed by this repository already exposes `IsUnion`, `UnionCaseTypes` and `IsClosed` could not be verified: the package is not in the local NuGet cache. Every proposed change that reads these members is therefore plausible until the package is inspected.

## Findings

### CM-1. A union is an undistinguishable struct in the public code model

- Where: `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Source/SourceNamedTypeImpl.cs:69-79` (`TypeKind` mapping), `:173` (`IsRecord`), `:133` (`IsReferenceType`); `Metalama.Framework/src/Metalama.Framework/Code/INamedType.cs:15` (summary lists "class, struct, interface, enum, delegate, or record"), `:189-202` (`IsReadOnly`, `IsRef`, `IsRecord`); `Metalama.Framework/src/Metalama.Framework/Code/TypeKind.cs:29,67` (obsolete `RecordClass` and `RecordStruct`).
- What happens today: Roslyn reports a union declaration as `TypeKind.Struct`, so `SourceNamedTypeImpl.TypeKind` returns `TypeKind.Struct`, `IsRecord` returns false, `IsReferenceType` returns false and `Constructors` lists the synthesized constructors. An aspect has no member to tell a union from a struct. The `[Union]` attribute is synthesized at emit time, so it is absent from `Attributes` for a union of the current compilation and present for a union read from a referenced assembly (plausible; it follows the pattern of the other synthesized attributes). `ImplementedInterfaces` contains `IUnion` because Roslyn adds it implicitly.
- Consequence class: silent wrong output. An aspect that treats the union as a struct and introduces an instance field or an auto-property produces code that the compiler rejects ("Instance fields, auto-properties or field-like events are not permitted"), with a diagnostic on generated code. `MulticastImplementation.cs:170-178` (`Metalama.Extensions/src/Metalama.Extensions.Multicast/`) and `EligibilityRuleFactory.cs:47,121,143,175` (`Metalama.Framework/src/Metalama.Framework/Eligibility/`) admit the union wherever they admit a struct.
- Proposed change: add `bool IsUnion { get; }` and `IReadOnlyList<IType> UnionCaseTypes { get; }` to `INamedType`, next to `IsRecord`, and document the union in the `INamedType` summary. Do not add a `TypeKind.Union` value: the precedent is `TypeKind.RecordClass` and `TypeKind.RecordStruct`, both obsolete with the message "TypeKind.Class and INamedType.IsRecord", and the exhaustiveness table shows that a new `TypeKind` value would need a new arm in 17 switches, 9 of which throw in the default arm. Implement `IsUnion` in `SourceNamedTypeImpl` from `ITypeSymbol.IsUnion` and `UnionCaseTypes` mapped through `Compilation.Factory.GetIType` in the current generic context, in the facade `SourceNamedType.cs:514-522` (same pattern as `IsRecord`), and as constants in `NamedTypeBuilder.cs:36`, `NamedTypeBuilderData.cs:364`, `IntroducedNamedType.cs:200` and `IntroducedExtensionBlock.cs:190` (all under `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Introductions/`). Add an eligibility rule `MustNotBeUnion` or make the field and auto-property introduction advice report an error when the target `IsUnion` is true (theme 04).
- Size: M (the Roslyn variant gating of CM-13 is most of the cost).
- Confidence: verified for the current behaviour; plausible for the Roslyn members.
- Open questions: whether `5.10.0-1.26365.3` already exposes `IsUnion` and `UnionCaseTypes`; whether the public API should also expose the synthesized `Value` property as a distinguished member.

### CM-2. `IsPartial` is false for a `partial union`, which reports `LAMA0048` wrongly

- Where: `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Source/SourceNamedTypeImpl.cs:329-352`; `Metalama.Framework/src/Metalama.Framework.Engine/Utilities/Roslyn/SyntaxKindExtensions.cs:33-35` (`IsTypeDeclaration` lists class, struct, interface, record and record struct) and `:41` (`IsBaseTypeDeclaration`); consumers `Metalama.Framework/src/Metalama.Framework.Engine/Pipeline/DesignTime/DesignTimeSyntaxTreeGenerator.cs:158-166` and `:940-951`, `Metalama.Framework/src/Metalama.Framework.Engine/AdviceImpl/Introduction/IntroduceMemberAdvice.cs:217`.
- What happens today: `IsPartial` reads the modifiers of the primary syntax only when the kind is in `IsTypeDeclaration`, an enum or a delegate. A `UnionDeclarationSyntax` matches none of the arms, so the modifiers default to empty and `IsPartial` is false even when the source says `partial union`. The design-time generator then reports `LAMA0048` ("Aspects add members to '{0}' but it is not marked as 'partial'") at `:162` and returns without generating anything, and the code fix offered for `LAMA0048` (`Metalama.Framework/src/Metalama.Framework.DesignTime/CodeFixes/TheCodeFixProvider.cs:57,111`) is offered for a type that already is partial.
- Consequence class: diagnostic reported (wrong), and the design-time artefacts of the union are never generated.
- Proposed change: add `SyntaxKind.UnionDeclaration` to `IsTypeDeclaration` (which also fixes `IsBaseTypeDeclaration`), then review each consumer of both properties: `SymbolExtensions.cs:289` (`IsPrimaryConstructor`, see CM-8), `CompileTimeCompilationBuilder.FindCompileTimeCodeVisitor.cs:77,81`, `CompileTimeCompilationBuilder.ProduceCompileTimeCodeRewriter.cs:1460,1530`, `DependencyAnalysisHelper.FindDeclaredTypesVisitor.cs:35,39`, `DependencyAnalysisHelper.FindDeclaredAndAttributeTypesVisitor.cs:41,45`. Extend the `KindCheckOptimizationAnalyzer` tests that pin `IsTypeDeclaration` (`Metalama.Framework/src/tests/Metalama.Framework.Engine.Analyzers.Tests/KindCheckOptimizationAnalyzerTests.cs:1115-1300`).
- Size: S.
- Confidence: verified.
- Open questions: none.

### CM-3. The design-time partial declaration of a union is emitted as `partial struct`

- Where: `Metalama.Framework/src/Metalama.Framework.Engine/Pipeline/DesignTime/DesignTimeSyntaxTreeGenerator.cs:698-771` (`CreatePartialType`), `:818-823` (`AddHeader`).
- What happens today: `CreatePartialType` switches on `type.TypeKind` and `type.IsRecord`. Once CM-2 is fixed, a partial union reaches the arm `TypeKind.Struct when !type.IsRecord` at `:749` and the generated file declares `partial struct Pet { ... }`. Roslyn reports `ERR_PartialTypeKindConflict` (CS0261) when two partial parts have different kinds (`SourceMemberContainerSymbol.cs`, checked for `IsPartial` on both parts), so the design-time compilation of the user's project shows an error in a generated file. `AddHeader` adds the "Generated by Metalama" comment only to class, struct, record, interface and namespace declarations, so a union part would carry no header. The same generator emits `partial class` for a closed class (`:722`); because Roslyn merges the modifiers of the parts with a bitwise OR and the C# standard §15.2.7 states that rule for `abstract`, `sealed` and `static`, a part without `closed` is expected to compile (plausible; no Roslyn test with a single `closed` part was found).
- Consequence class: diagnostic reported (a compiler error in the generated design-time file) for a partial union with introduced members; no impact for a closed class.
- Proposed change: add an arm `TypeKind.Struct when type.IsUnion` that builds a `UnionDeclarationSyntax` with the `partial` modifier, the `union` keyword, the identifier, the type parameters, no case list and no base list, and add `UnionDeclarationSyntax` to `AddHeader`. Write a `@TestScenario(DesignTime)` aspect test with a `partial union` target and commit its `.0.i.cs` output (the testing rules of `CLAUDE.md`).
- Size: M (a factory call on an experimental node plus the variant gating of CM-13, plus one design-time test).
- Confidence: verified for the current behaviour; plausible for the required shape of the part.
- Open questions: whether Roslyn accepts a partial union part without the case list. The grammar of the proposal writes `'(' case_types ')'` as mandatory, but the 5.10 grammar declares `ParameterList` optional and the parsing tests do not cover two parts. If every part must repeat the case list, the generator must copy `ParameterList` from the primary syntax, which is available through `type.GetPrimaryDeclarationSyntax()`.

### CM-4. Introduced types cannot be closed, and an introduced closed class would be emitted as `abstract`

- Where: `Metalama.Framework/src/Metalama.Framework/Code/DeclarationBuilders/INamedTypeBuilder.cs:13-49` and `IMemberOrNamedTypeBuilder.cs:64-95` (settable `IsSealed`, `IsAbstract`, `IsStatic`, `IsPartial`; no `IsClosed`); `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Helpers/ModifierHelper.cs:198-236` (`GetTypeSyntaxModifierList` emits `abstract` when `IsAbstract` and `sealed` when `IsSealed`); `Metalama.Framework/src/Metalama.Framework.Engine/AdviceImpl/Introduction/IntroduceNamedTypeTransformation.cs:61-92`; `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Introductions/Builders/NamedTypeBuilder.cs:52-53` (asserts class, struct, interface or extension and `!isRecord`); `Metalama.Framework/src/Metalama.Framework/Advising/IAdviceFactory.cs:1015-1035` and `Metalama.Framework/src/Metalama.Framework.Engine/Advising/AdviceFactory.cs:2050-2093` (`IntroduceClass` and `IntroduceInterface` only).
- What happens today: the public API has `IntroduceClass` and `IntroduceInterface`; there is no `IntroduceStruct`, `IntroduceRecord` or `IntroduceUnion`, and `NamedTypeBuilder` rejects records by assertion. A closed class cannot be introduced because no builder property exists. If `IsClosed` is added by copying `IsAbstract`, `ModifierHelper` would emit `abstract closed class`, which Roslyn rejects with `ERR_ClosedExplicitlyAbstract`.
- Consequence class: no impact today (the feature is absent); assertion or crash only for the future implementation if `ModifierHelper` is not adapted.
- Proposed change: add `bool IsClosed { get; set; }` to `INamedTypeBuilder` (closed applies to classes only, so not to `IMemberOrNamedTypeBuilder`), validate in the setter that `TypeKind` is `Class`, that `IsSealed` and `IsStatic` are false, and make `IsAbstract` read true when `IsClosed` is true, mirroring Roslyn. Store it in `NamedTypeBuilderData`, expose it in `IntroducedNamedType`, and in `GetTypeSyntaxModifierList` emit `Token(SyntaxKind.ClosedKeyword)` and skip `abstract` when the type is closed. Do not add union introduction for 2027.0: record introduction is not supported either, and a union declaration requires a case list that the builder has no model for.
- Size: M.
- Confidence: verified.
- Open questions: whether the `closed` token should be placed before `partial` (Roslyn requires `partial` immediately before `class`, so the order is `closed partial class`).

### CM-5. `IsClosed` is not exposed; the derived closedness is otherwise modelled correctly

- Where: `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Source/SourceMemberOrNamedType.cs:23` (`IsSealed`), `:36-44` (`IsAbstract`); `SourceNamedTypeImpl.cs:44` (`CanBeInherited`), `:175-178` (`HasDefaultConstructor`); `Metalama.Framework/src/Metalama.Framework/Eligibility/EligibilityExtensions.cs:740` (`MustNotBeAbstract`); `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/DerivedTypeIndex.cs:74-93` and `DerivedTypeIndex.Builder.cs:58-96`.
- What happens today: Roslyn sets the `Abstract` flag on a closed class, so `IsAbstract` is true, `IsSealed` is false, `CanBeInherited` is true, `HasDefaultConstructor` is false and `MustNotBeAbstract` rejects the type. All of this is semantically right. Nothing tells an aspect that the set of direct subtypes is complete, so validators that use `DerivedTypesOptions.IncludingExternalTypesDangerous` cannot take the shortcut that closedness allows, and an aspect cannot exploit the exhaustiveness guarantee of the proposal.
- Consequence class: no impact.
- Proposed change: add `bool IsClosed { get; }` to `INamedType`, read from `ITypeSymbol.IsClosed` in `SourceNamedTypeImpl`, false in builders and introduced types unless CM-4 is implemented, and mention in the `DerivedTypesOptions` documentation that for a closed type `DirectOnly` is exhaustive. Consider `GetClosedDerivedTypeInfo` as a faster source for `GetDerivedTypes` of a closed type only if the index cannot answer it already; the index already records every subtype in the current compilation, which is the whole set for a closed type.
- Size: S.
- Confidence: verified for the current behaviour; plausible for the Roslyn member.
- Open questions: whether `[CompilerFeatureRequired("ClosedClasses")]`, which the compiler synthesizes on every constructor of a closed class, appears in `IConstructor.Attributes` for constructors read from metadata, and whether any advice that copies constructor attributes (forwarding constructors, pulled parameters) would copy it. This is a linker and advice question (theme 04).

### CM-6. Hand-written lists of type-declaration syntax kinds omit `UnionDeclaration`

- Where: `Metalama.Framework/src/Metalama.Framework.Engine/Utilities/Roslyn/SyntaxExtensions.cs:20-22` and `:28-46` (`FindMemberDeclaration`, `FindMemberDeclarationOrNull`), `:56-79` (`FindSymbolDeclaringNode`), `:114-121` (`GetDeclaringType`); `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Helpers/CodeModelExtensions.cs:66-89` (`ToInsertPosition`); `Metalama.Framework/src/Metalama.Framework.Engine/Utilities/Roslyn/SymbolExtensions.cs:196-203` (`HasModifier`); `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Source/SourceMemberOrNamedType.cs:133-175` (`HasNewKeyword`); `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Source/SourceConstructor.cs:118-127`; `Metalama.Framework/src/Metalama.Framework.Engine/Linking/SymbolExtensions.cs:22-63` (`GetDeclarationFlags`). The complete list, including the linker, compile-time and test-framework sites, is in the exhaustiveness table.
- What happens today, for the code-model sites: `ToInsertPosition(ISymbol)` takes the primary declaration of the union type (a `UnionDeclarationSyntax`) and calls `FindMemberDeclaration`, which walks up the ancestors until it finds a kind in the list at `:30-36`. The union kind is not in the list, so the walk continues to the enclosing namespace declaration, which is in the list, and the insert position becomes `After` the namespace declaration rather than `Within` the union; members introduced into a union are therefore positioned outside the type. When the union is declared in the global namespace the walk reaches the compilation unit, returns null, and `FindMemberDeclaration` throws `AssertionFailedException` at `:21`. The same applies to a synthesized union member, whose position is computed from `symbol.ContainingType.GetPrimaryDeclarationSyntax()` at `:86-88`. `GetDeclaringType` returns the enclosing type of the union instead of the union. `HasModifier` returns false for every modifier of a union type (harmless: the type modifier list is built from `IsStatic`, `IsAbstract` and `IsSealed`, not from `HasModifier`). `HasNewKeyword` reaches the default `MemberDeclarationSyntax` arm and answers from the union modifiers, which is correct.
- Consequence class: assertion or crash (global namespace) or silent wrong output (namespace) for any member introduced into a union; silent for the rest.
- Proposed change: add `SyntaxKind.UnionDeclaration` to each list. Where a list is a hand-written copy of Roslyn's `SyntaxFacts.IsTypeDeclaration`, replace the copy by the Roslyn helper, which `ReferenceIndexWalker.cs:211` already uses and which Roslyn updates for the new kind. Add a unit test in `Metalama.Framework/src/tests/Metalama.Framework.Tests.UnitTests/CodeModel/` that resolves `ToInsertPosition` for a union in the global namespace and for one in a namespace.
- Size: S for the code-model sites; the linker, templating and design-time sites are counted in their own themes.
- Confidence: verified.
- Open questions: none.

### CM-7. Syntax visitors have no `VisitUnionDeclaration` override

- Where: the 20 files listed in the exhaustiveness table, of which the code-model ones are `Metalama.Framework/src/Metalama.Framework.Engine/CodeModel/Helpers/DependencyAnalysisHelper.FindDeclaredTypesVisitor.cs:47-58` and `DependencyAnalysisHelper.FindDeclaredAndAttributeTypesVisitor.cs:63-90`.
- What happens today: Roslyn's generated `CSharpSyntaxVisitor.VisitUnionDeclaration` calls `DefaultVisit`, which in a `CSharpSyntaxWalker` visits the children and in a `CSharpSyntaxRewriter` rewrites the children. The Metalama visitors therefore descend into the members of a union but skip the logic they run at the type level. For the two dependency visitors this means that a union declared in a file is not recorded as a declared type, so the design-time dependency graph does not know that the file declares it; a change to the union does not invalidate the aspects that depend on it (silent). The templating, compile-time, linker, reference-graph, formatting and design-time diff visitors are listed in the table with a one-line consequence each and belong to themes 02, 04 and 05.
- Consequence class: silent wrong output.
- Proposed change: add `VisitUnionDeclaration` overrides that route to the same helper as `VisitStructDeclaration`. Because `UnionDeclarationSyntax` is marked experimental in the prerelease grammar, the overrides need the experimental diagnostic suppressed until the stable grammar drops the attribute (`FACTS.md`). Extend `Find-KindOptimizationCandidates.ps1` or the `KindCheckOptimizationAnalyzer` with a rule that flags a visitor overriding `VisitStructDeclaration` without `VisitUnionDeclaration`, so that the omission cannot recur.
- Size: S per visitor; M in total across themes.
- Confidence: verified.
- Open questions: none.

### CM-8. The synthesized union members reach the code model with syntax the model does not expect

### CM-9. A run-time union in a file that also contains compile-time code breaks the compile-time compilation

- Where: `Metalama.Framework/src/Metalama.Framework.Engine/CompileTime/CompileTimeCompilationBuilder.FindCompileTimeCodeVisitor.cs:58-99`; `CompileTimeCompilationBuilder.ProduceCompileTimeCodeRewriter.cs:210-217`, `:340-370`, `:530-560`.
- What happens today: `FindCompileTimeCodeVisitor` decides whether a syntax tree is fed to the compile-time rewriter; it never visits a union, which is correct because a union is run-time code. - Consequence class: build or restore error, with a misleading message.
- Proposed change: override `VisitUnionDeclaration` in `ProduceCompileTimeCodeRewriter` and route it to `VisitTypeDeclaration`; add a compile-time unit test with a run-time union and an aspect in one file. This belongs to theme 02; it is recorded here because the crash originates in the missing visitor override of CM-7.
- Size: S.
- Confidence: verified.
- Open questions: none.

### CM-10. Every engine reference to the new Roslyn members needs a variant strategy

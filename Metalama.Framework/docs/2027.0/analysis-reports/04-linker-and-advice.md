# 04. Linker, advice, code formatting and introduction builders: impact of C# 15 and Roslyn 5.10

Scope: `Metalama.Framework.Engine/Linking`, `Advising`, `AdviceImpl`, `Transformations`, `Formatting`, `CodeModel/Introductions`, and the design-time partial-type generator insofar as it emits type declarations. All paths are relative to `/home/user/Metalama/Metalama.Framework/src/`. Line numbers refer to the checked-out branch named in `FACTS.md`.

## Summary

1. Unions are the only C# 15 feature that reaches the linker as a new syntax node kind, and the linker has no dispatch for it. Both the injection rewriter and the linking rewriter dispatch on the five known `TypeDeclarationSyntax` kinds and let everything else fall through to the Roslyn default visit. Any advice that injects a member into a union, or overrides a member of a union, ends in an `AssertionFailedException` in `LinkerInjectionRegistry` (LK-1); advice that only adds attributes or interfaces is silently dropped.
2. The helper kind lists (`IsTypeDeclaration`, `FindMemberDeclarationOrNull`, `GetDeclarationFlags`, the record kind switches) all omit `UnionDeclaration`, which is also why `partial union` reports `IsPartial == false` and why the design-time generator would emit `partial struct` for a union (LK-3, LK-4).
3. Any fix that names `UnionDeclarationSyntax`, `SyntaxKind.UnionDeclaration`, `ClosedKeyword` or `BreakStatementSyntax.Name` must be variant-gated: the same sources compile for Roslyn 5.0.0 (`Metalama.Framework.Engine.5.0.0.csproj`) where these members do not exist, and in 5.10.0-1.26365.3 they carry `ExperimentalUrl`. The type-declaration paths can be fixed without naming the new types by dispatching on the abstract `TypeDeclarationSyntax` (proposed in LK-1).
4. Extension indexers: `AdviceFactory.IntroduceIndexer` rejects extension-block targets by design (LK-6); overriding a source extension indexer follows the tested extension-property path and should work when inlined, and reports LAMA0699 otherwise (LK-7).
5. Labeled `break` and `continue` do not break any linker rewrite (no rewriter reconstructs break or continue statements; the rewriters are Roslyn `CSharpSyntaxRewriter` descendants that pass unknown children through), but inlining copies user labels verbatim, and labeled loops make label collisions between a template body and a target body realistic (LK-12).
6. `closed` classes pass through the rewriters unchanged; introduced types cannot be declared `closed` (LK-5); the design-time partial parts omit `closed` (LK-4, open question on Roslyn's partial rule).
7. Collection-expression `with(...)` elements and the "static members in interfaces" feature have no impact in these themes.

## Proposal files used

The `proposals/csharp-15.0` folder of `dotnet/csharplang` (fetched 2026-09-03) contains exactly five files: `closed-hierarchies.md`, `collection-expression-arguments.md`, `extension-indexers.md`, `labeled-break-continue.md`, `unions.md`. All five were read. There is no proposal file for "static members in interfaces": the Roslyn `docs/Language Feature Status.md` lists the C# 15 row "Non-virtual static interface members without DIM runtime support" with the implementation pull request `https://github.com/dotnet/roslyn/pull/83097` and no proposal link. The meaning is therefore taken from that row: the compiler stops requiring runtime support for default interface members when an interface declares non-virtual static members, which matters for the `net472` desktop flavour of PB-2027.0. Facts quoted from the proposals:

- `unions.md`: grammar `attributes? struct_modifier* 'partial'? 'union' identifier type_parameter_list? '(' case_types ')' struct_interfaces? type_parameter_constraints_clause* ('{' struct_member_declaration* '}' | ';')`; "is lowered to a struct declaration"; synthesized "a public constructor for each of the case_types" and "`public object? Value { get; }`"; "Instance fields, auto-properties or field-like events are not permitted"; "Explicitly declared public constructors with a single parameter are not permitted"; "Explicitly declared constructors must use a `this(...)` initializer". In the Roslyn 5.10 grammar (`eng/src/GenerateMetaSyntaxRewriter/Syntax-5.10.0.xml:1954-1978`) the case list is stored in the inherited `ParameterList` field of `UnionDeclarationSyntax`.
- `closed-hierarchies.md`: "Allow `closed` as a modifier on classes"; a closed class is implicitly abstract and cannot be `sealed` or `static`; derived classes must be in the same assembly; the document does not address partial declarations. The task background also names interfaces, structs and enums; the proposal names classes only, so this report treats classes as the verified scope.
- `labeled-break-continue.md`: `break_statement: 'break' identifier? ';'`; the label refers to "the nearest enclosing switch_statement or iteration_statement labeled with that identifier"; stored as an optional identifier on `BreakStatementSyntax` and `ContinueStatementSyntax` (`Syntax-5.10.0.xml:1296`, field `Name` of type `IdentifierNameSyntax`, `ExperimentalUrl`).
- `collection-expression-arguments.md`: `with_element: 'with' argument_list`, must be the first element, may be combined with spread elements.
- `extension-indexers.md`: `indexer_declaration` is added to `extension_member_declaration`; "an extension block that declares an indexer must provide a named receiver parameter"; no static extension indexers; "extension members do not have an implicit or explicit `this`"; lowered to `get_Item` / `set_Item` static implementation methods; `init` accessors are not allowed.

## Findings

### LK-1. The injection rewriter does not visit union declarations; injected members targeting a union are never inserted and the registry asserts

- Where:
  - `Metalama.Framework.Engine/Linking/LinkerInjectionStep.Rewriter.cs:316-324` overrides `VisitClassDeclaration`, `VisitStructDeclaration`, `VisitInterfaceDeclaration`, `VisitRecordDeclaration` and `VisitExtensionBlockDeclaration`, each delegating to `VisitTypeDeclaration<T>` (line 359). There is no `VisitUnionDeclaration` and no override of `VisitCore`/`DefaultVisit` that would catch other `TypeDeclarationSyntax` kinds.
  - `VisitTypeDeclaration<T>` (`LinkerInjectionStep.Rewriter.cs:359-455`) is the only place that consumes `InsertPosition( After, member )` (line 398-402) and `InsertPosition( Within, node )` for type nodes (line 405-409), applies primary-constructor member-level transformations (line 370-374), injects introduced interfaces (`GetIntroducedInterfacesForTypeDeclaration`, line 364, backed by `LinkerInjectionStep.TransformationCollection.cs:334-344`), and rewrites the type's attribute lists (line 451-452).
  - `VisitMember` (`LinkerInjectionStep.Rewriter.cs:1113-1134`) routes a nested union through `this.Visit( member )`, that is through Roslyn's default visit, so nested unions get the same treatment as top-level ones.
  - Insert positions: `CodeModel/Helpers/CodeModelExtensions.cs:66-90` computes the position of a source declaration from `FindMemberDeclaration()`; `Utilities/Roslyn/SyntaxExtensions.cs:23-45` (`FindMemberDeclarationOrNull`) lists every member kind except `UnionDeclaration`, so for a union type symbol the walk continues to the enclosing `NamespaceDeclaration` or `FileScopedNamespaceDeclaration`, the `is BaseTypeDeclarationSyntax` test at line 73 fails, and the result is `InsertPosition( After, <namespace> )`, which no visitor consumes. For a member introduced into a union, `CodeModel/Introductions/BuilderData/NamedDeclarationBuilderData.cs:25-42` produces `InsertPosition( Within, <UnionDeclarationSyntax> )`, which is consumed only from `VisitTypeDeclaration`. For an override of a source member of a union, `AdviceImpl/Override/OverrideMemberTransformation.cs:41` produces `InsertPosition( After, <MethodDeclarationSyntax> )`, which is consumed only from the per-member loop of `VisitTypeDeclaration`.
  - `Linking/LinkerInjectionRegistry.cs:147` calls `GetCanonicalSymbolForInjectedMember` (lines 323-341) for every `InjectedMember`; line 326 does `GetRoot().GetCurrentNode( injectedMember.Syntax ).AssertNotNull()`. A member that was never inserted has no tracked node and `GetCurrentNode` returns `null`.
- What happens today: every advice kind that produces an `InjectedMember` (override, introduction, contract with auxiliary member, initializer method, interface member implementation) on a union or on a member of a union ends with `AssertionFailedException` from `LinkerInjectionRegistry.cs:326`. `IntroduceAttribute` on the union type and `ImplementInterface` with no member to introduce do not produce an `InjectedMember`; their effect is silently lost because `RewriteDeclarationAttributeLists` (line 70-137) and `GetIntroducedInterfacesForTypeDeclaration` are only reached from `VisitTypeDeclaration`. Members of a union are still visited by Roslyn's default visit, so `VisitParameter` (line 1606) and `VisitAccessorDeclaration` (line 1760) run, but `VisitMethodDeclarationCore` (line 1553), `VisitConstructorDeclarationCore` (line 1482), `VisitPropertyDeclarationCore` (line 1652) and `VisitIndexerDeclarationCore` (line 1712) do not, so contracts and initializer statements targeting union members are also never injected.
- Consequence class: assertion or crash (member-producing advice); silent wrong output (attribute-only and interface-only advice). No effect on a union that no aspect touches: the default visit reproduces the node unchanged.
- Proposed change: add a dispatch that does not depend on the Roslyn 5.10 API surface, so that the same source builds for the 5.0.0 variant (`Metalama.Framework.Engine.5.0.0/Metalama.Framework.Engine.5.0.0.csproj:7` compiles `../Metalama.Framework.Engine/**/*.cs`) and does not touch the `[Experimental]` `UnionDeclarationSyntax`: override `VisitCore` in `Rewriter` (it derives from `SafeSyntaxRewriter`, `Metalama.Framework.Sdk/Utilities/Roslyn/SafeSyntaxRewriter.cs`, whose `VisitCore` is the extension point named in its documentation) and route any `TypeDeclarationSyntax` whose kind is not one of the five handled kinds to `VisitTypeDeclaration<TypeDeclarationSyntax>`. That method already uses only members of the abstract base (`Members`, `BaseList`, `ParameterList`, `OpenBraceToken`, `WithMembers`, `WithBaseList`, `WithParameterList`, `WithOpenBraceToken`, `WithIdentifier`), so it compiles unchanged. Extend `FindMemberDeclarationOrNull`, `FindSymbolDeclaringNode` and `GetDeclaringType` (`SyntaxExtensions.cs:23-45, 51-70, 113-119`) with a `current is TypeDeclarationSyntax` test instead of a kind list. Add a linker test (`Metalama.Framework.Tests.LinkerTests/Tests`) and aspect tests under a new `Aspects/CSharp15/Unions` folder guarded with `ROSLYN_5_10_0_OR_GREATER`, as the two existing tests already do (`FACTS.md`).
- Size: M (with LK-2 and LK-3, which the fix must include to be useful).
- Confidence: verified for the skipped dispatch and the insert-position computation; the exact exception site (line 326) is verified by reading, not by running.
- Open questions: whether the stable Roslyn 5.10 removes the `ExperimentalUrl` from `UnionDeclarationSyntax` (`FACTS.md` notes the generator will then start producing code for it); whether Roslyn reports a union symbol with `TypeKind.Struct` (the code model mapping in `CodeModel/Source/SourceNamedTypeImpl.cs:69-78` throws `InvalidOperationException` for any other value, which would fail before the linker runs; this belongs to the code-model analyst).

### LK-2. The linking rewriter has no union dispatch; once LK-1 is fixed, union members would be injected but never linked

- Where: `Linking/LinkerLinkingStep.LinkingRewriter.cs:37-85` overrides the same five kinds; `GetMembersForTypeDeclaration` (line 87-246) is the only path that calls `LinkerRewritingDriver.RewriteMember`, `GetSharedTypeMembers` and the record helpers. `Linking/LinkerLinkingStep.cs:66-69` removes the `__LinkerInjectionHelpers__` tree from the final compilation.
- What happens today: unreachable, because LK-1 fails first. After LK-1 alone is fixed, a union would keep the intermediate form: the original member unchanged, the override members present as separate declarations that still call the original member through annotated expressions, and any helper-member reference (`LinkerInjectionHelperProvider`, for example async-void or event-raise helpers) left dangling after the helper tree is removed.
- Consequence class: silent wrong output (aspects have no effect) or build or restore error (dangling helper references).
- Proposed change: same technique as LK-1: route unknown `TypeDeclarationSyntax` kinds to `node.WithMembers( List( this.GetMembersForTypeDeclaration( node ) ) )`, the treatment already used for interfaces (line 63-64) and extension blocks (line 79-85). Unions have no primary constructor to strip and no positional properties, so `RewriteRecord`/`RewriteClass` logic is not needed.
- Size: S (part of LK-1).
- Confidence: verified for the missing dispatch; plausible for the consequence.

### LK-3. Syntax-kind lists and record special cases that exclude unions

- Where (each site was read):
  - `Utilities/Roslyn/SyntaxKindExtensions.cs:33-35` (`IsTypeDeclaration`) and its users: `Utilities/Roslyn/SymbolExtensions.cs:283-291` (`IsPrimaryConstructor`), `CodeModel/Source/SourceNamedTypeImpl.cs:329-350` (`IsPartial`: a `partial union` reports `false`), `CodeModel/Source/SourceConstructor.cs:92-94`, `Linking/Inlining/ImplicitLastOverrideReferenceInliner.cs:72`.
  - `Linking/SymbolExtensions.cs:20-63` (`GetDeclarationFlags`): the kind list at lines 26-31 omits `UnionDeclaration`; the `default` branch at line 62 throws `AssertionFailedException`.   - `Linking/LinkerLateTransformationRegistry.cs:145-152` and `186-192`: `Single( d => d.IsKind( ClassDeclaration ) || ... RecordStructDeclaration ) && ParameterList != null )`. A union always has a `ParameterList` (the case list). These methods run only when a primary constructor was removed, which cannot happen for a union because `IsPrimaryConstructor` is false, so no crash today.
  - Record kind switches: `Linking/LinkerSyntaxHandler.cs:104-105`, `Linking/LinkerAnalysisStep.SemanticBodyAnalyzer.cs:244,418`, `Linking/LinkerAnalysisStep.SubstitutionGenerator.cs:908`, `Linking/LinkerAnalysisStep.AspectReferenceCollector.cs:203`, `Linking/LinkerRewritingDriver.cs:323`, `Linking/LinkerRecordHelper.cs:45,65`. They special-case record-synthesized members (`Equals`, `EqualityContract`) whose primary declaration syntax is the record declaration.   - `Utilities/Roslyn/SymbolExtensions.cs:196-201` (`HasModifier`): a `unsafe` modifier on a union declaration is not seen, so `ModifierHelper.GetTypeSyntaxModifierList` would not propagate `unsafe`. Cosmetic.
  - `Utilities/Roslyn/SyntaxExtensions.cs:113-119` (`GetDeclaringType`) and `51-70` (`FindSymbolDeclaringNode`): for a node inside a union it walks past the union to the enclosing type or returns `null`.
- What happens today: `partial union` reports `IsPartial == false`, so the design-time generator reports `TypeNotPartial` (`Pipeline/DesignTime/DesignTimeSyntaxTreeGenerator.cs:158-163`) and `IntroduceMemberAdvice.ValidateBuilder` reports `CannotIntroducePartialMemberToNonPartialType` (`AdviceImpl/Introduction/IntroduceMemberAdvice.cs:216-224`) for partial members introduced into a union. The other sites are latent.
- Consequence class: diagnostic reported (wrong diagnostic on `partial union`); assertion or crash for the latent sites once LK-1 is fixed and unions become reachable.
- Proposed change: replace kind lists by `node is TypeDeclarationSyntax` tests where the intent is "a declaration with members" (`IsTypeDeclaration` callers, `FindMemberDeclarationOrNull`, `GetDeclaringType`, `GetDeclarationFlags`), and keep the record-only lists for the record-synthesized-member logic. `IsPrimaryConstructor` must additionally exclude unions, because the union `ParameterList` is a case list and not a primary constructor; the safest test is `node is TypeDeclarationSyntax { ParameterList: not null } and not RecordDeclarationSyntax` combined with `RawKind != 9082` (numeric, see `FACTS.md`) until the stable Roslyn 5.10 removes the experimental attribute.
- Size: M.
- Confidence: verified for the code paths; plausible for the union symbol shape (depends on how Roslyn reports the synthesized constructors and their `DeclaringSyntaxReferences`).
- Open questions: does Roslyn return the `UnionDeclarationSyntax` as the declaring syntax of the synthesized case constructors (like record primary constructors) or nothing (like implicit default constructors)? This decides whether `GetDeclarationFlags` and `ImplicitLastOverrideReferenceInliner` (line 72-73, `throw`) are reached.

### LK-4. Design-time partial declarations copy neither the `union` keyword nor the `closed` modifier

- Where: `Pipeline/DesignTime/DesignTimeSyntaxTreeGenerator.cs:697-790` (`CreatePartialType`): modifiers are `static? partial` only (lines 710-714); the switch on `type.TypeKind` and `type.IsRecord` (lines 720-789) emits `class`, `record`, `struct`, `record struct` or `interface` and throws `AssertionFailedException( "Unknown type kind" )` otherwise. `AddPartialModifierToTypes` (lines 506-522) handles the same five kinds for introduced nested types.
- What happens today: for a union target (assuming the Roslyn symbol reports `TypeKind.Struct`, the lowering named by the proposal), the generated file contains `partial struct U { ... }` next to the source `partial union U(...)`, which the compiler rejects (partial parts must be of the same declaration kind). If Roslyn reports a new `TypeKind` value instead, `SourceNamedTypeImpl.TypeKind` throws before this point. For a `closed partial class C`, the generated part is `partial class C`; this is legal if the compiler merges `closed` across parts the way it merges `abstract` and `sealed` (both are also omitted today at line 710-714 and this works), but the proposal does not say.
- Consequence class: build or restore error at design time for unions (the generated file does not compile, so the IDE shows errors); no impact for `closed` unless Roslyn requires the modifier on every part.
- Proposed change: add a `union` case that emits a `UnionDeclarationSyntax` with the source case list copied (the case list is required on every part or on exactly one part; the proposal grammar makes it mandatory in the declaration, an open question for partial parts). This case cannot be written without the 5.10 API and therefore needs a variant-specific file (a `.generated`-style per-variant source, or a `#if ROSLYN_5_10_0_OR_GREATER` block, which would be the first such block in production code per `FACTS.md`). For `closed`, add a test in `Aspects/CSharp15` with `@TestScenario(DesignTime)` on a `closed partial class` and adopt whatever the compiler requires.
- Size: S for `closed` (test only, unless the compiler requires the modifier); M for `union` because of the variant gating.
- Confidence: verified for the generator; plausible for the compiler behaviour.
- Open questions: partial-part rules for `closed` and for the union case list in the Roslyn implementation.

### LK-8. Advice on unions after LK-1: synthesized constructors and the field prohibition produce compiler errors

- Size: M (rules and tests) or S (blanket diagnostic).

### LK-9. Inlining copies user labels verbatim; labeled loops make label collisions between template and target realistic

- Where: `Linking/Substitution/InliningSubstitution.cs:34-73` inlines the substituted body as a `FlattenableBlock`; `Linking/LinkerLinkingStep.CleanupBodyRewriter.cs:93-108, 194-205` flattens those blocks into the enclosing statement list; `Linking/LexicalScopeFactory.Visitor.cs:86-91` collects user label identifiers so that the linker's own labels (`__aspect_return_N`, `epilogue`, `postBase`) are unique, but no substitution renames user labels (grep of `LabeledStatement` under `Linking/` finds only `CleanupBodyRewriter`, `SemanticBodyAnalyzer`, `RemoveTrivialLabelRewriter`, `LexicalScopeFactory.Visitor` and `BlockWithReturnBeforeUsingLocalSubstitution`); templates may contain labeled statements (`Templating/TemplateAnnotator.cs` has no `VisitLabeledStatement` override; only `goto` is rejected at lines 2601-2606).
- What happens today: a label can only be useful with `goto`, which templates cannot use, so a template body and a target body never carried the same label. With C# 15, `outer: foreach (...) { ... break outer; }` becomes an ordinary idiom, and a template that contains such a loop and is inlined into a target method that also declares `outer` yields two `outer:` labels in one block after flattening (CS0140), or a label shadowing a label of a contained scope when the blocks are not flattened (CS0158). The same happens when one template with a labeled loop is applied to a method that is later inlined into another override of the same template (two copies of the same template are never inlined into one method because a semantic is inlined only when referenced once, `linker-inlining.md`, "Why exactly once"), so the practical case is template versus target.
- Consequence class: build or restore error (in the transformed compilation).
- Proposed change: add a label-renaming substitution applied to inlined bodies: collect `LabeledStatementSyntax` identifiers of the inlined body, allocate unique names through `LexicalScopeFactory.GetLexicalScope( destination ).GetUniqueIdentifier`, and rewrite `LabeledStatementSyntax.Identifier`, `GotoStatementSyntax.Expression`, and the `Name` of `BreakStatementSyntax` and `ContinueStatementSyntax`.

### S-19. C# 15: raise errors when a label is used in a template

- Issue type: User Story
- Labels: `enhancement`, `Area-Framework-Templates`, `Area-Framework`
- Milestone: `2027.0`
- Repositories: `metalama/Metalama`
- Size: M
- Blocked by: S-13, S-15
- Findings: [TP-3](../02-syntax-generator-and-templates.md), [LK-9](../04-linker-and-advice.md),
  [UT-17](../06-user-tfm-patterns-tests-docs.md)

---

A label in a template is unsupported and must be reported. The mechanism that reports an unsupported language
feature already exists and is already used for a jump: `TemplateAnnotator.VisitGotoStatement` at
`Metalama.Framework/src/Metalama.Framework.Engine/Templating/TemplateAnnotator.cs:2601-2605` calls
`ReportUnsupportedLanguageFeature` for the `goto` keyword. The work of this story is to call the same helper at three
further sites. `TemplateAnnotator` has no `VisitLabeledStatement` override, so a labeled statement in a template is
not rejected today, and the label of a `break` or of a `continue` statement is not classified either. Independently
of the templates, the inlining substitution copies the labels of user code verbatim into a destination that may
already declare them, and labeled loops make that collision realistic for the first time.

#### Context

Section 4 of [`DECISIONS.md`](../DECISIONS.md) forbids a labeled `break` or `continue` inside a template rather than
supporting it, because the label belongs to a loop whose scope may differ from the scope of the statement that names
it and the annotator cannot classify it. Section 4b extends that answer to the label itself, for the same reason and
for one more: before C# 15 the only use of a label was `goto`, which the annotator already reports, so a label in a
template was already useless in practice, and rejecting the jumps while accepting the labels would leave the feature
half supported.

One distinction decides where the rejection is written. The rejection belongs to the annotator, which reads the
template that the aspect author wrote. The template compiler rewriter generates a labeled statement of its own, at
`TemplateCompilerRewriter.cs:2408`, and handles labeled statements at `TemplateCompilerRewriter.cs:2214` and at
`TemplateExpansionContext.cs:832`. That generated statement does not pass through the annotator, so a rejection
placed in the rewriter instead of in the annotator would break the generated output.

Run-time code that an aspect transforms is not affected, because the annotator runs only inside a template. Section 4
requires that such code keeps working once the syntax model is regenerated by S-13, and that requirement is the
second half of this story: the inlining substitution moves user code, and the collision it creates is between a label
of the moved body and a label of the destination.

#### Scope

- Add a `VisitLabeledStatement` override to `TemplateAnnotator` that reports the unsupported language feature on the
  label, through the same `ReportUnsupportedLanguageFeature` helper that `VisitGotoStatement` calls at
  `TemplateAnnotator.cs:2601-2605`.
- Report the same error from the visit of a `break` and of a `continue` statement in `TemplateAnnotator` when the
  statement carries a name, on the name token.
- Leave the labeled statement that `TemplateCompilerRewriter.cs:2408` generates untouched, and add a test that pins
  that generation, because a rejection written in the rewriter rather than in the annotator would break it.
- Confirm that the rejection fires only inside a template, because the annotator runs under the guard that tests
  whether the code is inside a template, and add a test that a run-time labeled loop outside a template is untouched.
- Rename the labels of an inlined body when the destination already declares them, allocating unique names through
  the existing lexical scope factory, and rewrite the labeled statement, the `goto` target and the name of `break`
  and `continue` consistently.
- Gate the strongly typed part of that rewrite on the latest Roslyn variant, per S-13, because the name of `break`
  and `continue` is a member that the lower variant does not have.
- Add the two metric unit tests and the observability aspect test with a labeled loop in a getter, which record that
  the metric providers count nodes and statements generically and need no new case.
- Extend the inlining documentation with the reason a label is renamed.

#### Acceptance criteria

- A labeled statement in a template is reported with a diagnostic on the label, and a labeled `break` or `continue`
  in a template is reported with a diagnostic on the name.
- The labeled statement that the template compiler rewriter generates is still produced, and the test that pins it
  passes.
- An aspect that overrides a method whose body contains a labeled loop produces code that compiles, including when
  the destination declares the same label.
- A labeled `break` in transformed run-time code targets the same loop it targeted in the source.
- The metric providers are unchanged, and the tests that pin them pass.

#### Not in scope

This story does not support labels in templates, which sections 4 and 4b of [`DECISIONS.md`](../DECISIONS.md) exclude.
